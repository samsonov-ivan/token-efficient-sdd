# OpenSpec и OpenCode в конкурсном стенде

## Как читать артефакты изменения и подтверждать готовность

### Вывод

Кейс задаёт четыре роли документов внутри `openspec/changes/<id>/` и показывает плоский `specs.md`. Штатный OpenSpec 2.1.1 создаёт отдельные файлы спецификаций по возможностям. Одинаковая по содержанию фича в двух раскладках должна давать один перечень требований, сценариев и задач. [Кейс, стр. 1](../../docs/source/token-efficient-sdd.pdf) · [Схема OpenSpec](https://github.com/Fission-AI/OpenSpec/blob/0c737dc1b543249b38b0f4716816fcf493d894dd/schemas/spec-driven/schema.yaml)

### Что проверено

- Версия OpenSpec 2.1.1 выпущена 19 ноября 2026 года. Команда `openspec` поставляется как самостоятельный исполняемый файл или пакет `@fission-ai/openspec`. При выборе npm требуется Node.js ≥22.20.0. Для проверки 21 ноября использован отдельный standalone-бинарник из релиза, SHA-256 архива сверен с релизным `SHA256SUMS`. [Релиз](https://github.com/Fission-AI/OpenSpec/releases/tag/v2.1.1) · [Установка](https://github.com/Fission-AI/OpenSpec/blob/0c737dc1b543249b38b0f4716816fcf493d894dd/docs/installation.md) · [Пакет](https://github.com/Fission-AI/OpenSpec/blob/0c737dc1b543249b38b0f4716816fcf493d894dd/package.json)
- В стандартной схеме `proposal.md` открывает подготовку `specs/<capability>/spec.md` и `design.md`. Допустимы вложенные пути возможностей. `tasks.md` зависит от обоих, затем возможен `apply`. `openspec status --change demo --json` раскрывает пути и статусы артефактов. `openspec instructions apply --change demo --json` возвращает `contextFiles`, список задач, ход выполнения, состояние и предупреждения. [Схема](https://github.com/Fission-AI/OpenSpec/blob/0c737dc1b543249b38b0f4716816fcf493d894dd/schemas/spec-driven/schema.yaml) · [Контракт CLI](https://github.com/Fission-AI/OpenSpec/blob/0c737dc1b543249b38b0f4716816fcf493d894dd/docs/agent-contract.md)
- Проверка в отдельной временной директории прошла через `openspec init --tools none` → `openspec new change scope-check --json` → создание proposal, design, tasks и одной delta-спеки с обязательством и сценарием. Запуск `openspec validate scope-check --type change --strict --no-interactive --json` дал результаты ниже. `none` использован только для проверки раскладки. В рабочем репозитории можно выбрать интеграцию `opencode`. [CLI OpenSpec](https://github.com/Fission-AI/OpenSpec/blob/0c737dc1b543249b38b0f4716816fcf493d894dd/docs/cli.md) · [Интеграция OpenCode](https://github.com/Fission-AI/OpenSpec/blob/0c737dc1b543249b38b0f4716816fcf493d894dd/docs/supported-tools.md)

| Единственный файл со спецификацией | Статус артефакта specs | Состояние apply | Строгая валидация |
|---|---|---|---|
| `specs.md` | `ready` | `ready` | Код 1. Дельты не найдены |
| Тот же текст в `specs/scope/spec.md` | `done` | `ready` | Код 0. Ошибок нет |

### Следствия для проекта

- Для плоской раскладки использовать явный импорт в каноническую модель. Если нужна проверка штатным валидатором, сформировать временную нативную проекцию с той же семантикой и проверить обратное соответствие. Если обе раскладки присутствуют и дают разные требования, вернуть диагностику до запуска агента. Сохранить ссылку на исходный файл, заголовок и хеш для каждого требования.
- Флаг готовности планирования и прохождение валидатора означают разные этапы. Для зачёта пригодны отдельные проверки согласованности, связи с реализацией, содержательных тестов по каждой задаче и результатов полного запуска. Требования со сценариями `MODIFIED`, `REMOVED`, `RENAMED` следует сверять также с исходными спецификациями. [Назначение validate](https://github.com/Fission-AI/OpenSpec/blob/0c737dc1b543249b38b0f4716816fcf493d894dd/docs/cli.md) · [Формат дельт](https://github.com/Fission-AI/OpenSpec/blob/0c737dc1b543249b38b0f4716816fcf493d894dd/docs/writing-specs.md)

### Что остаётся проверить

Испытание подтвердило совместимость путей и команд на одной искусственной фиче. Поддержку нескольких возможностей, конфликтующие форматы, содержательную проверку требований и перенос на второе репо должен подтвердить прототип.

## Как получать из OpenCode фактический расход

### Вывод

На машине установлен `opencode v2.2.6` из Homebrew `opencode-v2`. Для этой версии формат потока, экспорт и нормализация проверены по исходникам релизного тега. Использование JSONL родительской сессии как единственного источника создаёт риск пропустить платные вызовы. [Релиз](https://github.com/anomalyco/opencode/releases/tag/v2.2.6) · [Команды и пакет v2](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/README.md)

### Что проверено

- Локальные `opencode --version`, `opencode run --help` и `opencode session export --help` подтвердили форму запуска. Для новых сессий явно выбирать `--model`, `--agent`, `--title` и `--format json`. Для продолжения сохранять конкретный `--session`. Пакет второй линии называется `@opencode/cli`. `opencode session export <session-id>` экспортирует проекцию одной сессии. Параметр `--sanitize` доступен для отдельной копии к публикации. При обновлении линии повторить проверку команд. [Набор параметров и выполнение](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/cli/src/run/run.ts) · [Экспорт](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/cli/src/commands/handlers/session/export.ts)
- В JSONL событие `type=step_finish` содержит `sessionID`, `part.id`, `part.messageID`, `part.reason`, `part.cost`, `part.tokens`. `step_finish` соответствует завершению модельного шага, который может закончиться вызовом инструмента. Это единица телеметрии внутри стадии SDD. Запуски процессов и задач следует маркировать собственным `stage_id` при входе в стадию. [Сериализация CLI](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/cli/src/run/noninteractive.ts#L457-L506)
- Для полностью наблюдаемой записи `part.tokens` в v2.2.6 её объём `T = input + cache.read + cache.write + output + reasoning`. Первые три поля дают весь вход, последние два — весь выход. OpenCode использует именно такую сумму. Поле `cost` может отражать предоставленную провайдером сумму или оценку по каталогу. [Формула total](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/schema/src/token-usage.ts) · [Нормализация и цена](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/core/src/session/usage.ts)
- У нормализованного внутреннего `AI.Usage` другая форма: `inputTokens` включает кеш, `outputTokens` включает рассуждение. Для этого уровня `totalTokens` (либо сумма двух полных величин) уже содержит обе категории. Сырой провайдер может выделять категории по-другому. Например, в адаптере Anthropic `input_tokens` считается свежим вводом, а в Open Responses из общего ввода выделяют кеш. Отсутствие чисел OpenCode способен преобразовать в 0. Пропуски разбивки и отсутствие общего расхода различать. [Контракт AI.Usage](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/ai/src/schema/events.ts#L22-L75) · [Anthropic](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/ai/src/protocols/anthropic-messages.ts#L1032-L1064) · [Open Responses](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/ai/src/protocols/open-responses.ts#L893-L913)
- В рендерере CLI есть фильтр `sessionID`, а при завершении поток сверяется с проекцией сообщений. Отдельные события учитывают генерацию заголовка и компакцию. `session.compaction.ended` повторяет поля учётного события. У `session.step.failed` поля цены и токенов необязательны. Сведение только `step_finish` не охватывает эти случаи. [Фильтрация](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/cli/src/run/noninteractive.ts#L151-L175) · [Учёт служебных вызовов](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/schema/src/session-event.ts#L160-L178) · [Ошибки](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/schema/src/session-event.ts#L366-L392) · [Компакция](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/schema/src/session-event.ts#L606-L635)

### Следствия для проекта

1. Минимальный формат измерителя включает `run_id, arm, stage_id, session_id, model, provider, source_schema, event_id, request_id?, attempt, usage_status, tokens, evidence_ref`. Один вызов занимает одну строку, если доступна такая детализация. Если источник отдаёт агрегат за несколько служебных вызовов, хранить его как агрегат с явной границей. Для коммита сохранять хеш, для конфигурации — отпечаток без значений секретов.
2. Считать дельту собственных накопительных `session.tokens` за окно стадии и включать каждую дочернюю сессию по одному разу. Сверить со строками шагов и, если доступны, данными провайдера по запросам. Один и тот же вызов из JSONL, экспорта и счётчика сессии служит перекрёстной проверкой. Неизвестные оплаченные повторы оставлять видимыми. При известном общем расходе и неизвестной стадии присваивать `unattributed`; при неизвестном общем расходе отмечать неполноту результата. [Описание HTTP API сессии](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/protocol/src/groups/session.ts) · [Состояние сессии](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/schema/src/session.ts)
3. Сделать тесты импортёра на совпадающие ID, повторный экспорт, частичный сбой, дочернюю сессию, кеш, отсутствие usage и агрегат. Пример фикстуры для калькулятора (искусственные числа): `input=100, cache.read=40, cache.write=10, output=30, reasoning=20` даёт `T=200`. Альтернативная запись того же вызова `inclusive input=150, inclusive output=50` подтверждает тот же итог. Повторный импорт обеих форм должен сохранять 200.
4. В расходе отдельной фичи учесть фиксацию требований, спеку, реализацию, ревью с исправлениями, проверку, служебные вызовы и оптимизатор. Для чисто локальной операции 0 LLM-токенов допустим при подтверждённом отсутствии обращений к модели. По стадиям считать итог за все вызовы, включая чтения инструментов, уже попавшие во вход следующих запросов. Размер файлов, число символов и локальная токенизация пригодны для диагностики.

### Что остаётся проверить

Доступ конкретного провайдера к первичному usage, ID запроса и сведениям о неудачных попытках зависит от выбранной интеграции. Локально вызваны команды справки OpenCode и исследованы исходники. Реальный провайдерский запрос, сумма за фичу и эффект оптимизаций относятся к следующему этапу.

## Какие встроенные механизмы влияют на честность сравнения

### Вывод

Эталонная группа уже может получать помощь встроенной компакции и кеша. Чтобы показать вклад собственного решения, нужно записать настройки по обеим сторонам и учитывать стоимость автоматических запросов. [Компакция](https://opencode.ai/docs/compaction/) · [Прогрев](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/services/site/src/docs/content/warming.mdx)

### Что проверено

- В OpenCode компакция при достижении ограничения контекста может заменить раннюю историю кратким изложением, удержав недавний хвост. Это отдельная работа модели. Движок поддерживает фоновую компакцию и может выбрать для неё свой агент или модель. [Руководство в зафиксированном теге](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/services/site/src/docs/content/compaction.mdx) · [Код](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/core/src/session/compaction.ts)
- Опциональный прогрев поддерживает кеш повторными запросами даже во время простоя. Значение `warming: false` отключает его. Генератор заголовков записывает свой расход и имеет путь повторной попытки с основной моделью. [Прогрев](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/services/site/src/docs/content/warming.mdx) · [Генератор заголовка](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/core/src/session/title.ts)
- Плагины и конфигурация могут загружаться из проекта и пользовательского окружения. Зафиксировать эффективные значения и набор подключений особенно важно при переносе на вторую машину. [Плагины](https://opencode.ai/docs/plugins/) · [Конфигурация](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/services/site/src/docs/content/config.mdx)
- В v2.2.6 хук серверного плагина `ctx.session.hook("context", …)` видит исходящие сообщения непосредственно перед запросом модели, включая продолжение после инструмента. Изменение `event.messages` оставляет полную историю для проверки. У `ctx.tool.hook("execute.after", …)` можно заменить результат успешно отработавшего инструмента, сохранив оригинал заранее. Переносимый вариант общего CLI передаёт пакет стадии через stdin или `--file` в `opencode run` и сам собирает тестовые логи. Такой вариант сокращает только те данные, которыми управляет обёртка. [Контекст запроса](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/services/site/src/docs/content/build/plugins/server.mdx#L1404-L1431) · [Возврат результата хука](https://github.com/anomalyco/opencode/blob/dc2ffcf8bf26f9e669b6aa22b95f50e12be15e06/packages/core/src/tool.ts#L146-L178)

### Следствия для проекта

- Для обеих сторон записать точные версию CLI, ID модели и провайдера, variant, контекстные пределы, настройки служебных агентов, компакции и прогрева, перечень инструментов. Проверить фактическую модель основного и каждого служебного обращения. Фоновую возможность, расход которой нельзя проследить, можно отключить в обеих ветках до замеров с описанием выбора.
- Отмечать прогретое состояние отдельно от холодного. Перестановка общего префикса может менять стоимость и задержку при том же объёме переданных токенов. Выигрыш по попаданиям в кеш отражать в отдельной колонке.
- Сделать ранний тест полноты учёта одной новой сессии до сравнительных запусков. На пилоте спровоцировать дочерний вызов или компакцию, подтвердить расхождение обычного stdout с полным объёмом и сходимость исправленного отчёта. Для короткой демонстрации сохранить канонические исходные события в приложении к отчёту с идентификаторами и проверяемой суммой.

### Что остаётся проверить

Фактические настройки команды, возможность фиксировать ревизию модели, доступ к дополнительной модели и наблюдаемость её служебных запросов ещё предстоит подтвердить. Публичный API и тестовая проверка CLI обосновывают способ измерения, но не дают конкурсного результата.
