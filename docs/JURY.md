# Frugal SDD для жюри

**Есть два живых сравнения сжатия инструментального вывода на DeepSeek.** Они показывают расход при работе со сводкой и при дополнительном чтении полного журнала. Для полной фичи отдельно проверяются сопоставимость обоих плеч, качество и расход по стадиям. [Кейс и критерии](../case/token-efficient-sdd.pdf)

[Скачать офлайн-показ](collaboration/defense-preview.zip) · [Состав комплекта и контрольная сумма](collaboration/DEFENSE-PREVIEW.md). Распакуйте архив и откройте `prototype.mp4`. Рядом лежат отчёт, дашборд и записи демонстрационной пары с моделью `mock/replay`.

Из чистого клона можно открыть сводки живых проверок и проверить подписи двух оценок B0. Скрипт также пересчитывает суммы в опубликованных сводках B0.

```sh
git clone --branch codex/frugal-integration https://github.com/samsonov-ivan/token-efficient-sdd.git frugal
cd frugal
node scripts/verify-public-receipts.mjs
```

Исходные события живых прогонов хранит владелец. Для независимого пересчёта токенов каждого вызова используется исходный архив.

## Экономия токенов · вес критерия 35 %

Оба опыта H-03 выполнены на `opencode-go/deepseek-v4.1-flash` с `max`. Когда достаточно данных из сводки, сжатие снижает RPT. Когда модель читает полный лог дополнительным вызовом, расход в этом опыте растёт. В обоих случаях модель выдаёт правильный хеш, полный лог совпадает побайтно, а расход сверяется с relay и SQLite. [Ответ по сводке](../bench/runs/summary/h03-go-newest-20261122.json) · [Чтение архива](../bench/runs/summary/h03-go-recovery-20261122.json) · [Протокол](probes/H03_GO.md)

В двух локальных парах H-01 на `yocto-queue` с Qwen3-4B-Instruct-2507 запуск второй задачи в новой сессии снизил суммарный расход стадии `apply` с 45 549 до 38 186 RPT (16,2%) и с 54 909 до 45 136 RPT (17,8%). В каждой паре сохранили одинаковые задания и инструкцию передачи контекста. Порядок плеч между парами поменяли. Все четыре итоговых снимка прошли 10/10 публичных проверок. [Первичные события и снимки](https://github.com/samsonov-ivan/token-efficient-sdd/blob/1c0b516e2fed5340613d874df82c1649aa74d41f/docs/probes/local-h01-qwen3-path.zip) · [Офлайн-пересчёт и повтор тестов](https://github.com/samsonov-ivan/token-efficient-sdd/blob/1c0b516e2fed5340613d874df82c1649aa74d41f/docs/probes/LOCAL-LLM.md#офлайн-проверка-с-чистого-клона)

В предварительном CSV-пилоте живой base принят, а opt остановился на `verify` из-за транспортной ошибки Go. Подтверждённая часть расхода opt выше полного расхода base. Для полной фичи конкурсный процент экономии ещё не установлен. Отчёт строится из исходных архивов и опубликованных сводок командой `node packages/cli/bin/frugal.js report bench/runs --out report` после сборки проекта. [Сводка CSV-пилота](../bench/runs/summary/h03-csv2-pilot-1-comparison.json)

В повторе на полной CSV-фиче оба живых плеча H-03 прошли независимую подписанную приёмку. Расход вырос с 3 692 446 до 3 828 449 RPT (+3,68%). Дополнительных списаний не было. Пилот использует отдельный публичный бриф CSV. Конкурсная калибровка Ф0/E0 на фиче M продолжается. [Сравнение и ссылки на приёмку](../bench/runs/summary/h03-csv3-pilot-1-comparison.json)

## Сохранение качества · 25 %

У лимитов прошли 119/119 публичных и 29/30 закрытых тестов. В числе подтверждённых дефектов — ответ HTTP 500 на допустимое смещение страницы истории. У CSV прошли все 95/95 публичных и 16/16 закрытых тестов, однако при фильтрации за допустимую граничную дату исчезал перевод. Оба прогона прошли по одному раунду ревью. Оценщик отклонил оба снимка. Независимая приёмка конкурсного сценария лимитов остаётся открытой. [Приёмка лимитов](../bench/runs/summary/max-f0-repeat-first-f1f8742-1-base-a1-quality.json) · [Приёмка CSV](../bench/runs/summary/csv-s-b0-f1f8742-1-base-a1-quality.json) · [Контракт качества](QUALITY.md)

На отдельной ревизии CSV с явными примерами публичного контракта базовый прогон прошёл независимую подписанную приёмку. Сводка содержит покрытие, результаты обеих групп тестов и пересчитанный расход. Исходный оракул применён и к этой ревизии. [Приёмка base предварительной пары](../bench/runs/summary/h03-csv2-pilot-1-base-a1-quality.json)

## Универсальность моделей · 15 %

В проекте зафиксированы живые B0 на DeepSeek и Kimi и отдельный одношаговый ответ небольшой локальной SmolLM2-360M. Сравнение расхода и покрытия требований на малой и большой моделях для одной полной фичи остаётся открытым. [Результат Kimi](../bench/runs/summary/kimi-f0-second-1adba4c-1-base-a1-quality.json) · [Протокол SmolLM2](probes/WP00.md)

Обе попытки провести полную пару на локальной Qwen3 остановились на стадии спецификации. Первая прервалась при загрузке навыка OpenSpec до создания `proposal.md`. После восстановления навыка оба плеча создали proposal, design и спецификацию, затем достигли лимита шагов до появления `tasks.md`. Реализация, ревью и verify остались за пределами обеих попыток. [Протокол и архивы полного цикла](https://github.com/samsonov-ivan/token-efficient-sdd/blob/1c0b516e2fed5340613d874df82c1649aa74d41f/docs/probes/LOCAL-LLM.md#qwen3--полный-конвейер)

## Портативность · 10 %

На исходном коде `yocto-queue@72a8fa9` тот же исполнитель H-01 провёл изменение `peekLast()` через спецификацию, две сессии реализации, полное ревью и verify. OpenCode 1.19.6 исполнил заданные локальным mock-провайдером операции. Штатные тесты AVA прошли до и после изменения (7 и 8 соответственно), типы проверены через tsd. Новые проверки JavaScript и TypeScript обе обнаружили отсутствие метода на исходном коммите. В архиве лежат патч, журналы тестов, вывод ревью и события 37 обращений. [Первичные материалы, ZIP](probes/yocto-queue-h01.zip) · [Сводка](../bench/runs/summary/yocto-queue-h01-native.json) · [Команды повтора](../scripts/fixtures/yocto-queue.md)

Для Go-библиотеки `google/uuid` воспроизведены исходные тесты. На отдельных открытых фикстурах OpenCode 1.19.6 и 2.3.2 проверена передача handoff и сжатие журнала Git с 902 до 486 символов с восстановлением полного текста по SHA-256. [Go](../bench/runs/summary/portability-base/google-uuid-full/result.json) · [Handoff](../bench/runs/summary/h01-native-opencode.json) · [Журнал Git](../bench/runs/summary/h03-native-loopback.json)

## Где расходуются токены · 15 %

В обеих опубликованных сводках B0 больше всего токенов ушло на реализацию. Генератор отчёта показывает RPT, число вызовов и долю расхода по стадиям по первичному архиву. Поэтому прототип выдаёт исполнителю дословную выборку связанных требований и передаёт результат следующей задаче через handoff. [Лимиты переводов](../bench/runs/summary/max-f0-repeat-first-f1f8742-1-base-a1-quality.json) · [CSV](../bench/runs/summary/csv-s-b0-f1f8742-1-base-a1-quality.json) · [Капсулы](../packages/cli/src/capsule.ts) · [Сессии задач](../packages/cli/src/task-sessions.ts)

В контролируемом опыте на двух коротких задачах новая сессия сократила объём тела HTTP-запросов реализации с 60 946 до 58 902 байт. Оба служебных запроса второй задачи сэкономили по 1 022 байта истории. Проверяющий может сопоставить исходные восемь тел запросов, набор инструментов и результаты тестов.
