# Frugal SDD для жюри

**Процент экономии на полной фиче пока не установлен.** В открытом комплекте можно посмотреть работу прототипа, проверить учёт токенов двух настоящих базовых прогонов и увидеть, почему независимая приёмка отклонила оба результата. [Кейс и критерии, стр. 1](../case/token-efficient-sdd.pdf)

[Скачать офлайн-показ](collaboration/defense-preview.zip) · [Состав комплекта и контрольная сумма](collaboration/DEFENSE-PREVIEW.md). Распакуйте архив и откройте `prototype.mp4`. Рядом лежат отчёт, дашборд и записи демонстрационной пары с моделью `mock/replay`.

Комплект поставляется в отдельной командной ветке. Из чистого клона можно проверить подписи оценщика открытыми ключами из каталога `bench/runs/summary/` и пересчитать суммы в опубликованных сводках.

```sh
git clone --branch codex/frugal-friend https://github.com/samsonov-ivan/token-efficient-sdd.git frugal
cd frugal
node scripts/verify-public-receipts.mjs
```

Исходные события двух живых прогонов хранит владелец. Для независимого пересчёта токенов каждого вызова требуется его архив.

## Измеренная экономия · 35 %

В обоих прогонах B0 работала `opencode-go/deepseek-v4.1-flash` с `max`. На лимиты переводов пришлось 8 458 902 сырых токенов (RPT) за 143 вызова, на CSV-выгрузку — 3 814 248 за 90. Дополнительное списание по подписке составило $0 в каждом случае. Чтобы вычислить экономию, каждой фиче нужен сопоставимый принятый прогон с оптимизациями и принятый исходный результат. [Лимиты](../bench/runs/summary/max-f0-repeat-first-f1f8742-1-base-a1-quality.json) · [CSV](../bench/runs/summary/csv-s-b0-f1f8742-1-base-a1-quality.json)

## Сохранение качества · 25 %

У лимитов прошли 119/119 публичных и 29/30 закрытых тестов. В числе подтверждённых дефектов — ответ HTTP 500 на допустимое смещение страницы истории. У CSV прошли все 95/95 публичных и 16/16 закрытых тестов, однако при фильтрации за допустимую граничную дату исчезал перевод. Оба прогона прошли по одному раунду ревью. Оценщик отклонил оба снимка. Сохранение качества при оптимизации предстоит подтвердить на паре. [Приёмка лимитов](../bench/runs/summary/max-f0-repeat-first-f1f8742-1-base-a1-quality.json) · [Приёмка CSV](../bench/runs/summary/csv-s-b0-f1f8742-1-base-a1-quality.json) · [Контракт качества](QUALITY.md)

## Универсальность моделей · 15 %

В проекте зафиксированы живые B0 на DeepSeek и Kimi и отдельный одношаговый ответ небольшой локальной SmolLM2-360M. Сравнения экономии и покрытия требований на малой и большой LLM пока нет. [Результат Kimi](../bench/runs/summary/kimi-f0-second-1adba4c-1-base-a1-quality.json) · [Протокол SmolLM2](probes/WP00.md)

## Портативность · 10 %

На исходном коде `yocto-queue@72a8fa9` тот же исполнитель H-01 провёл изменение `peekLast()` через спецификацию, две сессии реализации, полное ревью и verify. OpenCode 1.19.6 исполнил заданные локальным mock-провайдером операции. Штатные тесты AVA прошли до и после изменения (7 и 8 соответственно), типы проверены через tsd. Новые проверки JavaScript и TypeScript обе обнаружили отсутствие метода на исходном коммите. В архиве лежат патч, журналы тестов, вывод ревью и события 37 обращений. Измерение экономии на внешней модели для этого репозитория ещё предстоит. [Первичные материалы, ZIP](probes/yocto-queue-h01.zip) · [Сводка](../bench/runs/summary/yocto-queue-h01-native.json) · [Команды повтора](../scripts/fixtures/yocto-queue.md)

Для Go-библиотеки `google/uuid` воспроизведены исходные тесты. На отдельных открытых фикстурах OpenCode 1.19.6 и 2.3.2 проверена передача handoff и сжатие журнала Git с 902 до 486 символов с восстановлением полного текста по SHA-256. [Go](../bench/runs/summary/portability-base/google-uuid-full/result.json) · [Handoff](../bench/runs/summary/h01-native-opencode.json) · [Журнал Git](../bench/runs/summary/h03-native-loopback.json)

## Где расходуются токены · 15 %

В таблице приведены RPT стадии и её доля в полном расходе конкретного B0. Обе колонки относятся к исходному процессу на разных фичах. [Исходные числа для лимитов](../bench/runs/summary/max-f0-repeat-first-f1f8742-1-base-a1-quality.json) · [Исходные числа для CSV](../bench/runs/summary/csv-s-b0-f1f8742-1-base-a1-quality.json)

| Стадия | Лимиты переводов | CSV-выгрузка |
|---|---:|---:|
| Спецификация | 611 845 · 7,2 % | 535 787 · 14,0 % |
| Реализация | 5 159 367 · 61,0 % | 1 631 449 · 42,8 % |
| Ревью | 1 466 775 · 17,3 % | 1 203 539 · 31,6 % |
| Проверка | 1 220 915 · 14,4 % | 443 473 · 11,6 % |
| **Всего** | **8 458 902** | **3 814 248** |

На обеих фичах больше всего токенов ушло на реализацию. Поэтому прототип выдаёт исполнителю дословную выборку связанных требований и передаёт результат следующей задаче через handoff. Вклад каждого механизма в расход полной фичи требует отдельного парного замера. [Капсула задачи](../packages/cli/src/capsule.ts) · [Оркестратор сессий](../packages/cli/src/task-sessions.ts)

В контролируемом опыте на двух коротких задачах новая сессия сократила объём тела HTTP-запросов реализации с 60 946 до 58 902 байт. Оба служебных запроса второй задачи сэкономили по 1 022 байта истории. Проверяющий может сопоставить исходные восемь тел запросов, набор инструментов и результаты тестов.
