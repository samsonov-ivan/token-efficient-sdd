# Параллельная работа над Frugal

Два Codex работают в отдельных ветках одного GitHub-репозитория. Git переносит код и статус. Агент получает обновление при следующем `status` или `git fetch`, поэтому проверяет статус в начале задачи, после проверки и перед следующей правкой. Во время длительного ожидания активный агент сверяет статус примерно раз в минуту.

| Ветка | Ответственный | Статус | Работа |
|---|---|---|---|
| `codex/frugal-integration` | Владелец | [owner.md](owner.md) | Контрольные запуски, независимая приёмка, измерение и слияние проверенных результатов |
| `codex/frugal-friend` | Друг | [friend.md](friend.md) | Капсула, сжатие вывода и ревью по изменениям на открытых фикстурах |

```sh
git pull --ff-only
node scripts/peer-sync.mjs status
```

В каждом статусе верхняя запись содержит дату, завершённую работу, проверку, следующий шаг и вопрос другому участнику при необходимости. Обновляйте только свой файл. Для передачи результата добавьте свои файлы и запись статуса в коммит, затем сразу опубликуйте его.

```sh
node scripts/peer-sync.mjs publish
```

Команда публикует коммиты текущей ветки в одноимённую ветку `origin`. Подготовьте изменения через `git add` и `git commit` до публикации. При расхождении веток сохраните обе стороны, обсудите конфликт в статусе, затем согласуйте слияние. `main` остаётся отдельной веткой для согласованной интеграции.

Первые три блока готовы к началу работы на mock. С владельца остаются реальные контрольные запуски и независимая проверка. Интеграцию оптимизированного маршрута и живые сравнения планируйте по данным калибровки.
