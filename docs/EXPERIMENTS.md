### EXP-20261121-05. Живая проверка OpenCode Go и два кандидата B0 для Ф0

- **Цель.** Сверить настоящий поток Go с OpenCode CLI и SQLite. Затем дважды пройти полную фичу M `add-transfer-limits` штатным автономным B0 для приёмки WP-04. Два принятых B0 дают измерения M-M для E0.
- **Конфигурация.** Один провайдер `opencode-go` и модель `opencode-go/deepseek-v4.1-flash` для всех вызовов. OpenCode V1 1.19.6, OpenSpec 2.1.1. Доступность модели по официальному endpoint подтверждена авторизованным чтением каталога. Каждый B0 использует свежий клон, обычный цикл ревью и пустой набор флагов. Закрытая приёмка проводится отдельно по итоговому снимку.
- **Порядок.** После репетиции выполнить один короткий `--go-smoke`, проверить подписочный источник и `allowance`, сохранить манифест, первичный журнал и хеш квитанции. Затем последовательно запустить два B0, по одному слоту на прогон. На первом B0 сохранить SHA и хеш замороженных шаблонов, на каждом B0 — расход по стадиям из журнала вызовов, результат независимой приёмки и все попытки с их ID.
- **Бюджет и остановка.** Разрешена оставшаяся квота подписки, дополнительные списания с баланса ограничены $0. При сбое авторизации, исчерпании квоты, неизвестном расходе или расхождении телеметрии очередь останавливается. Провайдер и модель остаются одинаковыми во всей последовательности. [Условия запуска](../tools/runner/README.md#подписка-opencode-go)
- **Репетиция `99bbcbe`.** Оба синтетических B0 прошли стадии, затем остановились на сверке расхода. Харнесс применил требования подписочного биллинга к обычному mock replay при выключенном relay. Обе попытки сохранены. Перед живой серией нужен повтор dry-run после исправления. [Первая попытка](../bench/runs/go-dry-f0-99bbcbe-1-base-a1/manifest.json) · [вторая попытка](../bench/runs/go-dry-f0-99bbcbe-2-base-a1/manifest.json)

### EXP-20261121-04. Подписочный путь Go на потоковой фикстуре

- **Цель.** Запустить настоящий OpenCode V1 внутри Docker, передать запрос в локальный relay и восстановить отдельные счётчики Go из синтетического ответа Chat Completions. Проверить, что внешняя модель и учётная запись для этой репетиции не нужны.
- **Конфигурация.** `--mode baseline --model opencode-go/deepseek-v4.1-flash --go-smoke --dry-run --relay-fixture http://127.0.0.1:PORT/v1 --image frugal-runner:local-24`. OpenCode 1.19.6, OpenSpec 2.1.1, Node 24.15.0. SHA `3fd5068` в манифесте относится к временному репозиторию тестового запуска. Код раннера — `7e159e2` с измерителем `778b744`.
- **Результат.** Локальный сервер ответил на один вызов без заголовка авторизации. Измеритель сопоставил HTTP-запрос с сессией и шагом SQLite, подтвердил нулевое списание с баланса, сохранил стоимость по прайсу и расход квоты в отдельных полях. Конвейер фичи остаётся за пределами этого smoke. Повторный импорт из архива совпал с сохранённым результатом, `accepted=false`.
- **Данные.** [Манифест](../bench/runs/go-container-fixture-1-base-a1/manifest.json) · [relay](../bench/runs/go-container-fixture-1-base-a1/raw/relay.jsonl) · [учёт расхода](../bench/runs/go-container-fixture-1-base-a1/meter.json) · [вызов](../bench/runs/go-container-fixture-1-base-a1/calls.jsonl).
- **Независимые контроли на `99bbcbe`.** Сборка на чистом checkout, 69 тестов TypeScript и Biome прошли. На пересобранном Docker-образе подписочный ответ завершил smoke с полным учётом. Второй ответ имитировал списание с денежного баланса, был отклонён, запуск получил `failed`, итоговые расход и RPT остались неизвестными. ### EXP-20261121-02. Разбивка токенов OpenCode Go

- **Цель.** Проверить, сохраняет ли OpenCode V1 разбивку токенов, необходимую для WP-02. В журнале Go проверили поля реального запроса DeepSeek V4.1 Flash. Затем воспроизвели формат потокового ответа Chat Completions на локальном HTTP-провайдере и прогнали родительскую и дочернюю сессии через `frugal meter`.
- **Версии.** OpenCode 1.19.6, Frugal `5fec2e5`. Измеряемый код совпадает с `61ff986`, который был на ветке в начале проверки.
- **Результат.** В первом контроле совпали число вызовов, RPT и разбивка токенов. Во втором контроле запись в кэш передавалась в полях `usage.opencode.tokens`. Общий RPT сошёлся, а `step_finish` и SQLite включили запись в некэшированный вход. Указанная в тестовом ответе стоимость по прайсу отсутствует в `step_finish`. Значения рассчитаны в файлах сверки.
- **Следствие.** Измеритель `778b744` читает исходный `usage` из журнала relay, сверяет число вызовов и RPT, восстанавливает поля при известном перераспределении записи в кэш и отдельно учитывает списание, стоимость по прайсу и расход квоты. Интеграция перехвата в живом раннере, сверка потока Go и учёт реальных тарифицированных ретраев остаются открытыми. Владелец разрешил использовать всю оставшуюся подписочную квоту Go с лимитом дополнительных списаний $0. Серия E0 не запускалась. [Условия использования Go](OPENCODE_GO_HANDOFF.md)
- **Данные.** [Стандартный ответ](../bench/runs/wp02-go-usage-smoke-20261121/reconciliation.json), [запись в кэш](../bench/runs/wp02-go-cache-write-smoke-20261121/reconciliation.json). Исходные события, БД, тестовые ответы и сценарий воспроизведения находятся в `raw/` каждого прогона.

### Протокол первой демонстрационной пары

До первого сравнения сохраняем условие D-review из ADR-005. Первую полную пару на основной фиче рассматриваем в хронологическом порядке. При 3–5 фактических раундах в обоих плечах используем её в основной демонстрации. Иначе для демонстрации планируется отдельная пара с тремя одинаковыми обязательными обзорами. Выбор не зависит от размера экономии. Число повторов, модель, доступная квота и бюджет конкретной серии фиксируются отдельной записью перед запуском.
