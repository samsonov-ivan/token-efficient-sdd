# Офлайн-запись Frugal SDD

Из корня репозитория соберите CLI командой `npm run build`. Для рендера нужны Python 3.11+, Pillow 12.2.0, FFmpeg с libx264, ffprobe, jq и sqlite3. Скрипт содержит зависимость Pillow для uv. В Linux он использует DejaVu Sans и DejaVu Sans Mono, в macOS — Helvetica Neue и Menlo. Свои файлы шрифтов с кириллицей можно задать через `FRUGAL_FONT` и `FRUGAL_FONT_MONO`.

Чтобы записать техническую репетицию, используйте ID успешной проверки дочерней сессии из `scripts/check-meter-children.mjs`.

```sh
uv run --script analysis/record_demo.py bench/runs --preview wp02-child-smoke-03
```

В `report/preflight.mp4` появятся результаты родительской и дочерней сессий реального opencode с локальным mock-провайдером. Если в том же архиве есть проверенный ответ живой модели с записанной SSE, две заключительные сцены показывают эту отдельную проверку. Запись воспроизводит сохранённые события. Команда meter во время записи заново читает архив и сверяет результат с отчётом. Переменная `$TMP` в кадре обозначает временный каталог независимого пересчёта.

Для финального фильма выберите ID полной живой пары в отчёте. Подставьте его вместо `PAIR_ID`.

```sh
uv run --script analysis/record_demo.py bench/runs --pair PAIR_ID
```

Проверки из `analysis/report.py` подтверждают сопоставимость двух плеч, полную приёмку и качество серии по §4.3. Затем скрипт записывает расход по стадиям, состав токенов, ссылки на наиболее дорогие шаги, цепочку от требования до assertion и результаты проверок. В кадре видны исходные пути, модель, настройки и размеры выборок. Для обеих веток команда `frugal meter` выполняется заново с выводом во временный каталог. Режим `--pair` формирует `report/demo.mp4` после проверки длительности 4–6 минут, частоты, числа кадров и полного декодирования. Можно задать иной путь через `--out`.

Видеоряд предназначен для просмотра без звука. Перед сдачей просмотрите кадры с длинными путями и идентификаторами. Сгенерированные файлы MP4 остаются локальными.
