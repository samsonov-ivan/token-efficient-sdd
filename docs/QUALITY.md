# Проверка итогового снимка

`frugal gates` читает обычные отслеживаемые файлы из Git-объектов итогового коммита. Для чтения change создаётся временная копия OpenSpec. Выполняются локальные `openspec validate --strict`, `show --json` и `instructions apply --json`. Плоский `specs.md` проверяется в нативной проекции. Для плоского изменения существующей capability доступен `--capability`.

## Материалы проверяющего

Исполнитель завершает конвейер и оставляет итоговый Git-снимок. Независимый харнесс запускает весь публичный набор и затем закрытую приёмку. В отдельном каталоге сохраняются отчёты, публичный `expected.yaml` и `evidence.json`. Учёт затрат оценщика ведётся отдельно после конца конвейера.

Формат `evidence.json` задан типом `Evidence` в [types.ts](../packages/cli/src/quality/types.ts). Поле `final_commit` содержит полный SHA. Для каждого набора нужны вид (`public` или `hidden`), формат (`junit`, `jest`, `go`), путь относительно каталога доказательств, SHA-256 исходного отчёта, код завершения и `expected_tests`. Инвентарь обязательных тестов фиксируется независимо. Для регрессии он должен включать исходные тесты, для закрытой приёмки — все тесты замороженного оракула. В XML идентификатор имеет вид `classname::name`, в JSON Jest/Vitest берётся `fullName`, для Go — `Package::Test`.

В `review` записываются реальные раунды с номером, областью, обоснованием, решением и SHA коммита или Git-дерева. Хэш последнего одобренного состояния должен совпасть с проверяемым снимком. Харнесс отвечает за происхождение свидетельств ревью и проверку фактических вызовов через meter.

## Независимая оценка

```sh
node packages/cli/bin/frugal.js gates --repo "$FINAL_REPO" --change "$CHANGE" \
  --expected "$EXPECTED" --evidence "$EVIDENCE" --out "$QUALITY_DIR" --prepare
```

В `evaluator-request.json` есть ожидаемые сценарии, предложения по привязке фактически выполненных тестов, утверждения, список исходников и SHA запроса. Проверяющий читает исходные файлы через `git show COMMIT:PATH`, проверяет бизнес-правила и каждую принятую связь. Его JSON-ответ содержит `version: 1`, `reviewer`, `request_sha256`, `final_commit`, `semantic` и `links`. Для каждого требования записываются `requirement`, `verdict` (`pass` или `fail`) и конкретное обоснование в `reason`. Для каждой связи нужны `scenario`, `task`, `test`, а также `code` и `assertion` с полями `path`, `line` и `text` из итогового снимка. При подтверждённой связи с пропущенной меткой теста добавляются `inferred: true` и `reason`.

```sh
node packages/cli/bin/frugal.js gates --repo "$FINAL_REPO" --change "$CHANGE" \
  --expected "$EXPECTED" --evidence "$EVIDENCE" --out "$QUALITY_DIR" \
  --assessment "$ASSESSMENT" --infer
```

Если в заголовке или задаче пропущен ID, запрос содержит `change.missingIds` с исходным путём, названием и родительским требованием для сценария. Проверяющий может вернуть `aliases` с полями `kind`, `path`, `text`, `parent` при наличии, `id` из исходного чек-листа и `reason`. Фактический текст design или задачи связывается через `artifact_links` с точными `path`, `line`, `text`, `refs`, `reason` и номером `task` для чекбокса. Режим `--infer` применяет эти связи после проверки исходника и сохраняет их в `trace.json`. В покрытие входят только сценарии и задачи с прошедшим тестом и проверенной строкой утверждения.

Для дополнительной задачи документации метка `[no-test]` требует обоснования в задаче и решения проверяющего в `exempt_tasks: [{task,reason}]`. Обязательные задачи исходного чек-листа входят в знаменатель покрытия.

Для подписанной оценки проверяющий подписывает точные байты ответа ключом Ed25519. К команде добавляются `--signature FILE --reviewer-key PUBLIC.pem`. Открытый ключ поступает от владельца контура приёмки. В локальном доверенном режиме `links` и `semantic` также могут поступать непосредственно из файла независимого запускателя.

## Результат

В `trace.json` записываются сценарии, задачи, проверенные строки продуктивного кода и теста, ID раннера и пути к протоколу. В `gates.json` сохраняются метрики покрытия и согласованности, результат каждого теста, раунды и диагностические сообщения. `gates.md` содержит выявленные проблемы. `frugal consistency` без оценки выводит структурный результат и статус `semantic: unverified`.

Отсутствие обязательного теста, пропуск, ручное изменение отчёта, конфликт SHA, висящая ссылка или неподкреплённое утверждение делают соответствующий результат непригодным. Полный наблюдаемый закрытый набор даёт долю `Q_hidden`, включая упавшие проверки. Для неполного наблюдения значение равно `null`. Правила сравнения плеч и серий заданы в §4.3 ТЗ.
