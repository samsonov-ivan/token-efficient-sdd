## Q0. Which opencode is "current"? (V1 vs V2: a hard fork in the API surface)

### Takeaway
As of November 2026 there are two maintained lines with incompatible plugin and server APIs. **OpenCode 2** (npm `@opencode/cli` 2.3.2, `@opencode/plugin`, `@opencode/sdk`, `@opencode/client`) is the `dev` branch and the one the README installs. **OpenCode 1** (npm `opencode-ai` 1.19.6, `@opencode-ai/plugin`, `@opencode-ai/sdk`, published 2026-11-17, branch `v1`) is still released. Most third-party token plugins (DCP, tokenscope) target V1 only. Before writing a single line of plugin code, the team must pick a line. Config files and `.opencode/` agents, commands and skills are mostly portable between the lines. Plugins and HTTP clients are not.

### Inferences
- For a portable hackathon layer, the safest design is a plugin package that exports both V1 `server()` hooks and V2 `setup()`, plus external scripts that read tokens from `run --format json` (the JSON shape is the same in both lines, see Q1) or from the session export. Prefer token-saving that works through files (AGENTS.md, agent/command markdown, `instructions`), because both lines read those.
- If the jury environment is "opencode + OpenSpec" installed from npm `opencode-ai`, the team is on V1. Confirm with `opencode --version`.

- I did not verify whether V1 and V2 share the same `opencode.db` file or whether V2 migrates V1 sessions automatically. An `/api/experimental/migration/v1` route exists in the V2 client, but I did not read what it does.

## Q1. Headless automation and exact token accounting (run / serve / SDK / export / stats / storage / schema)

### Takeaway
Use `opencode run --format json` for A/B runs. It emits NDJSON events, and each `step_finish` event carries per-LLM-call `tokens` {input, output, reasoning, cache.read, cache.write} and `cost`. V1 and V2 both emit this shape. For exact per-stage numbers, also read child (subagent) sessions and auxiliary calls (title, compaction). In V1 these are **not** in the parent's JSON stream. V2 has dedicated `session.usage.recorded` events for them. `tokens.input` is **non-cached input only**, so total prompt size = input + cache.read + cache.write.

### Cited Findings
**`opencode run` (V1 1.19.6)**
- Flags: `--command`, `--continue/-c`, `--session/-s`, `--fork`, `--model/-m provider/model`, `--agent`, `--file/-f`, `--format default|json`, `--title`, `--attach http://host:port`, `--password/-p`, `--username/-u`, `--dir`, `--port`, `--variant`, `--thinking`, `--auto` ("Auto-approve permissions that are not explicitly denied"). `opencode run --attach http://localhost:4096` avoids "MCP server cold boot times on every run". `--share` is not in the 1.19.6 flag table. — [V1 docs: cli](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/v1/content/cli.mdx)
- In JSON mode, every line is `{type, timestamp, sessionID, ...data}`. The types emitted are `tool_use` (completed or errored tool part), `step_start`, `step_finish`, `text`, `reasoning`, plus errors. Events are filtered with `if (part.sessionID !== sessionID) continue`, so **parts of child (subagent) sessions are not emitted**. — [V1 source: cli/cmd/run.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/cli/cmd/run.ts)
- The `StepFinishPart` type is `{id, sessionID, messageID, type:"step-finish", reason, snapshot?, cost, tokens:{total?, input, output, reasoning, cache:{read, write}}}`. `AssistantMessage` has `parentID, modelID, providerID, mode, agent, summary?, cost, tokens{...same}`. — `@opencode-ai/sdk@1.19.6` `dist/v2/gen/types.gen.d.ts` ([npm](https://www.npmjs.com/package/@opencode-ai/sdk))
- Normalisation in `getUsage`: `input = inputTokens − cacheReadInputTokens − cacheWriteInputTokens` ("AI SDK v6 normalized inputTokens to include cached tokens… Always subtract cache tokens"), and `output = outputTokens − reasoningTokens`. Cache write falls back to provider metadata (`anthropic.cacheCreationInputTokens`, `vertex`, `bedrock.usage.cacheWriteInputTokens`, `venice`). Cost = input·price.input + output·price.output + cache.read·price.cache.read + cache.write·price.cache.write + reasoning·price.output, all per 1M. Context-tier pricing (`cost.tiers`, `experimentalOver200K`) applies, and GitHub Copilot uses `totalNanoAiu`. — [V1 source: session/session.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/session.ts)
- The session row stores aggregated columns `cost, tokens_input, tokens_output, tokens_reasoning, tokens_cache_read, tokens_cache_write`, and `parent_id` links subagent sessions. — [V1 source: session/session.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/session.ts)

**`opencode run` (V2 2.3.x)**
- Documented flags: `--standalone` (private server, recommended for CI), `--server <url>`, `--model`, `--continue`, `--format json` ("newline-delimited JSON for scripts"), `--file` (repeatable), `--agent`, `--session ses_…`, `--auto`, `--archived` (keeps scripted runs out of session lists). — [V2 docs: cli/commands](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/cli/commands.mdx)

- V2 `TokenUsageInfo = {input, output, reasoning, cache:{read, write}}`. `input = usage.nonCachedInputTokens` and `output = usage.visibleOutputTokens`. Cost: "What an endpoint says it charged beats the catalog… A reported zero is authoritative". Otherwise the catalog price is used, with reasoning billed at the output price. — [V2 source: core/src/session/usage.ts](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/usage.ts), [V2 client types](https://github.com/anomalyco/opencode/blob/dev/packages/client/src/promise/generated/types.ts)

### Inferences
- **Per-stage measurement recipe (V1).** Run each SDD stage as its own `opencode run --format json --agent <stage-agent> --model <m> --title <run-id>/<stage> "..."`, or `--command <openspec-cmd>`. Sum the `step_finish.part.tokens` fields, then add child sessions. Child sessions can be found with `GET /session/:id/children`, or with `opencode db "select id, parent_id, tokens_input, tokens_output, tokens_cache_read, tokens_cache_write, cost from session where parent_id = '<id>'" --format json`. The table and column names come from `toRow()` in session.ts. I did not verify the actual SQL table name.
- **Per-stage measurement recipe (V2).** Prefer the embedded `@opencode/sdk` with `events.subscribe()`. Aggregate `session.step.ended` (primary loop) and `session.usage.recorded` (title/compaction/generate) per sessionID, and walk `parentID` for subagents. Or call `experimental.session.stats({from, to, project})` before and after each run.
- Always report four numbers per stage: fresh input, cache.read, cache.write and output (+ reasoning). opencode's `input` excludes cache, so "input tokens" in opencode is not comparable with a provider dashboard's "prompt tokens" unless cache is added back.

### Gaps
- I did not verify how V2 `run --format json` handles subagent (`jobSessions`) step events. The code tracks child session IDs, but I did not confirm whether child `step_finish` lines are emitted.
- The exact V1 SQLite table names and the message/part JSON columns were not inspected (they live in `packages/core`, which was not checked out at v1.19.6).

## Q2. Plugin API: hooks/events, which can rewrite model context, and existing token plugins

### Takeaway
**V1** (`@opencode-ai/plugin`) gives the most direct context-rewriting hooks. `experimental.chat.messages.transform` mutates the in-memory message list before each LLM call, without persisting. `experimental.chat.system.transform` edits system strings. `tool.execute.after` can rewrite the tool `output` that is stored and sent to the model. `tool.definition` shrinks tool descriptions and schemas. `experimental.session.compacting` replaces the compaction prompt. **V2** (`@opencode/plugin`) replaces these with `ctx.session.hook("context" | "compaction" | "generate" | "title" | "prompt" | ...)`. The `context` hook edits system, messages, tools and options for the outgoing call only. V2 adds `ctx.session.instructions.entry.put` for cache-friendly injected context.

### Cited Findings
**V1 Hooks interface (exact names)**
- `Plugin = (input: PluginInput, options?) => Promise<Hooks>`, where `PluginInput = {client (SDK client), project, directory, worktree, serverUrl, $ (BunShell)}`. — [V1 source: plugin/src/index.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/plugin/src/index.ts)
- The hooks are: `dispose`, `event({event})`, `config(cfg)`, `tool: {[name]: ToolDefinition}`, `auth`, `provider`, `"chat.message"(input{sessionID, agent?, model?, messageID?, variant?}, output{message, parts})`, `"chat.params"(… , output{temperature, topP, topK, maxOutputTokens, options})`, `"chat.headers"(…, output{headers})`, `"permission.ask"(Permission, output{status})`, `"command.execute.before"(input{command, sessionID, arguments}, output{parts})`, `"tool.execute.before"(input{tool, sessionID, callID}, output{args})`, `"shell.env"(input{cwd, sessionID?, callID?}, output{env})`, `"tool.execute.after"(input{tool, sessionID, callID, args}, output{title, output, metadata})`, `"experimental.chat.messages.transform"({}, output{messages: {info, parts}[]})`, `"experimental.chat.system.transform"(input{sessionID?, model}, output{system: string[]})`, `"experimental.provider.small_model"`, `"experimental.session.compacting"(input{sessionID}, output{context: string[], prompt?: string})` ("`prompt`: If set, replaces the default compaction prompt entirely"), `"experimental.compaction.autocontinue"(…, output{enabled})`, `"experimental.text.complete"(input{sessionID, messageID, partID}, output{text})`, and `"tool.definition"(input{toolID}, output{description, parameters})` ("Modify tool definitions (description and parameters) sent to LLM"). — [V1 source: plugin/src/index.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/plugin/src/index.ts)
- Custom tools use `tool({description, args: zod shape, execute(args, ctx)})`, with `ctx = {sessionID, messageID, agent, directory, worktree, abort, metadata(), ask()}`. They return a string or `{title?, output, metadata?, attachments?}`, and `tool.schema = z`. — [V1 source: plugin/src/tool.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/plugin/src/tool.ts)
- **The `tool.execute.after` output is what the model sees.** In `session/tools.ts` the `output` object is passed to `plugin.trigger("tool.execute.after", …, output)` and then `return output`. A hook that rewrites `output.output` (for example, truncating test logs or summarising diffs) therefore changes the stored and model-visible tool result. — [V1 source: session/tools.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/tools.ts)
- **`experimental.chat.messages.transform` runs on every loop step**, on the freshly loaded `msgs`, before `MessageV2.toModelMessagesEffect(msgs, model)`. It also runs before compaction (`compaction.ts:379`). — [V1 source: session/prompt.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/prompt.ts), [compaction.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/compaction.ts)
- `experimental.chat.system.transform` runs in `llm/request.ts` after the system array is built. If a plugin produces more than 2 entries and the header is unchanged, OpenCode re-collapses them into `[header, rest.join("\n")]` (2 system messages, which matches the 2 system cache breakpoints). — [V1 source: session/llm/request.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/llm/request.ts)
- `tool.definition` is triggered per tool in the tool registry, and `chat.params`/`chat.headers` are triggered in `llm/request.ts`. — [V1 source: tool/registry.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/tool/registry.ts)

**V2 plugin API**
- `export default Plugin.define({ id, setup(ctx) {...; return cleanup} })` from `@opencode/plugin`. Plugins are configured with `"plugins": ["pkg", {"package": "./plugin/local", "options": {...}}]`. Local plugins are directories (`.opencode/plugins/<name>/index.ts`). The context exposes `ctx.location`, `ctx.options`, `ctx.storage` and the full client. — [V2 docs: build/plugins/server](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/build/plugins/server.mdx), [migrate-v1](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/migrate-v1.mdx)
- Session hooks (`ctx.session.hook(name, cb, {providerID?})`): `prompt` (edits user input before admission; "Edits become the canonical persisted user input"; runs once per admission), `context` (agent loop including tool continuations), `compaction` (`messages` = transcript being summarised; set `result` to skip the model call), `generate`, `title`, `experimental.model.resolve` (swap the model per request within the same provider), `model.request`, `http.request`/`http.response`, `experimental.ws.handshake|send|receive`, `retry`, and `fork`. For `context`: "Changes affect only the outgoing model call, not persisted history or configuration", and "A hook that should apply to every request must register for each kind". The event fields are `system: SystemPart[]`, `messages: Message[]`, `tools: Record<string, {description, input: JsonSchema}>`, `options{maxTokens, temperature, …}` and `agent`. The system part lists its sources in `metadata.experimental.instructions` as `{key, text}` (for example `core/date` and `core/environment`). — [V2 docs: build/plugins/server](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/build/plugins/server.mdx)
- Other V2 hooks are `ctx.permission.hook("evaluate")`, `ctx.shell.hook("create.before")` (command, cwd, timeout, shell, env) and `ctx.tool.hook("execute.before" | "execute.after")`. In `execute.after`, `event.result` can be replaced, as in the documented example `event.result = {...event.result, metadata: {...}}`. ### Inferences
- Best V1 levers for the SDD case:
  - `tool.execute.after`: compress test logs and diffs (keep failures and tail) before they enter history. This change is permanent, so it is cache-stable.
  - `experimental.chat.messages.transform`: dedupe repeated `read` outputs of spec files, and replace stale tool outputs with pointers. This is ephemeral per call, but it invalidates the cache from the first changed message.
  - `tool.definition`: shorten verbose tool descriptions for small models.
  - `experimental.session.compacting`: inject an SDD-aware summary template that keeps the task ID, the spec deltas and the review findings.
  - `chat.params`: set `maxOutputTokens` per agent.
- In V2, the equivalent is the `context` hook (ephemeral) plus `ctx.tool.hook("execute.after")` (persistent). Inject the current task's spec slice through `ctx.session.instructions.entry.put` instead of rewriting the system prompt.

### Gaps
- I did not confirm whether V2 `execute.after` result changes persist into history or affect only the model call. The docs show only metadata modification. Test this before relying on it.
- No independent, reproducible savings numbers for DCP were found in primary sources.

## Q3. Built-in context management (compaction, pruning, limits)

### Takeaway
V1.19.6: auto-compaction triggers when the last step's total tokens ≥ the usable window. The usable window is `limit.input − reserved` or `context − maxOutputTokens`, with `reserved` defaulting to min(20k, max output). Tool-output pruning is **opt-in** (`compaction.prune: false` by default). V2: summary compaction with `keep.tokens` (15k) verbatim tail, `buffer` "15%" (at least 16k), background pre-summarisation, optional provider-native compaction (OpenAI Responses), and a manual API. Neither line can help when fixed instructions and tool schemas dominate the window.

### Cited Findings
- V1 config keys: `"compaction": {"auto": true, "prune": false, "reserved": 10000}`. `auto` defaults to true; `prune` ("Remove old tool outputs to save tokens") defaults to `false`. — [V1 docs: config](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/v1/content/config.mdx)
- V1 overflow: `COMPACTION_BUFFER = 20_000`. `usable = limit.input ? limit.input − (compaction.reserved ?? min(20000, maxOutputTokens)) : context − maxOutputTokens`. `isOverflow` returns false if `compaction.auto === false` or `limit.context === 0`. Otherwise it compares `tokens.total || input+output+cache.read+cache.write` against `usable`. `OUTPUT_TOKEN_MAX = 32_000`, overridable by `OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX`. — [V1 source: session/overflow.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/overflow.ts), [provider/transform.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/provider/transform.ts)
- V1 compaction constants: `PRUNE_MINIMUM = 20_000`, `PRUNE_PROTECT = 40_000`, `TOOL_OUTPUT_MAX_CHARS = 2_000` (each tool result is truncated to 2000 chars + "[truncated]" when serialised for the summariser), `PRUNE_PROTECTED_TOOLS = ["skill"]`, and preserve-recent budget = `compaction.preserve_recent_tokens ?? clamp(floor(usable·0.25), 2_000, 15_000)`. A `compaction.tail_turns` key is also read. — [V1 source: session/compaction.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/compaction.ts)
- V1 prune algorithm: it returns immediately unless `cfg.compaction.prune` is set. It walks backwards, skips the last 2 user turns, stops at a previous summary, and keeps the newest 40k estimated tokens of completed tool outputs. If more than 20k of older output qualifies, it marks those parts `time.compacted`, and their output is replaced by "[Old tool result content cleared]". — [V1 source: session/compaction.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/compaction.ts)
- V1 env flags `OPENCODE_DISABLE_AUTOCOMPACT` (sets `compaction.auto=false`) and `OPENCODE_DISABLE_PRUNE` (sets `compaction.prune=false`). — [V1 source: config/config.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/config/config.ts)
- The V1 compaction system prompt (`agent/prompt/compaction.txt`, 630 bytes) reads: "You are a context summarization agent… produce a structured summary… preserve exact file paths and identifiers… prefer terse bullets… Respond in the same language as the conversation." Hidden agents `compaction`, `title` and `summary` exist. After compaction, a synthetic "continue" user turn is added unless `experimental.compaction.autocontinue` sets `enabled=false`. — [V1 source: agent/prompt/compaction.txt](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/agent/prompt/compaction.txt), [compaction.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/compaction.ts)
- V2 compaction settings: `auto` (true; also "recover once when a provider rejects a request as too long"), `background` (true), `keep.tokens` (15000), and `buffer` ("15%", at least 16k; accepts "1%"–"99%" or a token count). `agents.compaction.model` can name a cheaper summary model. Native compaction is set with `providers.<id>.settings.compaction.type: "native" | "summary"` and supports OpenAI Responses (encrypted checkpoint). Manual compaction: `opencode api post /api/session/<id>/compact --data '{}'`, which accepts an optional idempotency `id`. Limits: "It cannot create room when a request is mostly fixed instructions and tool schemas", and "Earlier messages remain stored even when they are no longer sent to the model". In the kept recent conversation, "long tool output is shortened and attachment data is replaced by a short description". The summary sections are Objective, requirements, decisions, completed/active work, blockers, Next Move and relevant files. — [V2 docs: compaction](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/compaction.mdx)
- V2 background compaction "reuses the prompt cache", and "a summary that is never used… still costs tokens". — [V2 docs: compaction](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/compaction.mdx)
- V2 per-step: "Start session history from the latest completed compaction" (#59020), and "Size session compaction from the provider's reported token count" (#59441). — [CHANGELOG](https://github.com/anomalyco/opencode/blob/dev/CHANGELOG.md)
- Searching `packages/core/src` and `packages/cli/src` for `OPENCODE_DISABLE_AUTOCOMPACT` and `OPENCODE_DISABLE_PRUNE` in V2 (`dev` at `edacc86`) returned no matches. — local grep of [anomalyco/opencode dev](https://github.com/anomalyco/opencode)

### Inferences
- For SDD runs of 8–12 tasks, auto-compaction is rarely the main saving: each task's run is typically far below the threshold. The real costs are (a) the fixed prefix (system + tools + AGENTS.md + skills) re-sent on every step, and (b) tool outputs (test logs, diffs, repeated file reads) that accumulate inside a task. In V1, enabling `compaction.prune: true` with a smaller effective protect window, via a plugin, is cheap.
- A custom `experimental.session.compacting` prompt, or a V2 `compaction` hook `result`, can produce an "SDD state" summary (task ID, done/remaining tasks, open review findings) that is far shorter than the generic one.

### Gaps
- I did not verify whether `/compact` still exists as a TUI command in V2 (V1 exposes `session.summarize`). The V2 docs only describe the API route.
- The exact V1 default for `tail_turns` was not checked.

## Q4. System prompt composition and per-agent overrides (sizes)

### Takeaway
V1 sends a large provider-specific base prompt (about 7–15 KB, roughly 2–4k tokens) unless the agent sets `prompt`. It then appends the env block (which includes `Today's date`), skills, AGENTS.md/CLAUDE.md/`instructions` and MCP instructions, and adds tool definitions (about 15 KB of descriptions alone for built-ins). V2's base prompt is tiny (about 1 KB) plus small provider addenda. A non-empty agent `prompt` (V1) or `system` (V2) **replaces** the provider base prompt, which is the single biggest static saving and works with any model.

### Cited Findings

### Inferences
- Rough fixed prefix in V1 with Claude: anthropic.txt (about 2k tokens) + env (about 0.1k) + tools (about 4–6k with schemas) + skills + AGENTS.md + MCP. Each skill and each MCP server adds more. Measure the real number per configuration from the first `step_finish` of a trivial prompt (`input + cache.write + cache.read`).
- Portable savings that need no model change:
  - Give SDD-stage agents a short `prompt`/`system`, which replaces the 8–15 KB base.
  - Deny unneeded tools per agent (webfetch, websearch, todowrite, task, lsp, question), since each removes its description and schema from every call.
  - Keep AGENTS.md short and move the spec into on-demand reads.
  - Avoid many skills and MCP servers in review and verify agents.

- The size of V2 built-in tool descriptions was not measured.

## Q5. Agents, subagents, commands; is subagent context isolated and are tokens separate?

### Takeaway
Subagents run in **child sessions with fresh context** (`parentID` = caller). Only the subagent's final text returns to the parent. The child's tokens are recorded on the child session, not the parent, so per-stage accounting must sum the session tree. Commands (`.opencode/command(s)/*.md`) support `$ARGUMENTS`, `$1..$n`, `` !`shell` `` and `@file` injection, plus `subtask: true` (V1) or `subagent: true` (V2) to keep the primary context clean.

### Cited Findings
- V1 agents use the `agent` map or `.opencode/agent(s)/*.md` / `~/.config/opencode/agent(s)/*.md`. Fields: `description`, `mode` (`primary|subagent|all`), `model`, `variant`, `temperature`, `top_p`, `prompt`, `steps` ("legacy `maxSteps` field is deprecated"; at the limit "the agent receives a special system prompt instructing it to respond with a summarization"), `disable`, `hidden`, `color`, `tools` (deprecated), `permission`, and `permission.task` (glob rules, last match wins). Built-ins are `build`, `plan`, `general` and `explore`, and the hidden ones are `compaction`, `title` and `summary`. — [V1 docs: agents](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/v1/content/agents.mdx)
- V1 `task` tool: creates a session with `parentID: ctx.sessionID`; takes a `task_id` parameter to "resume a previous task… continue the same subagent session"; returns `result.parts.findLast(type === "text")?.text`. Background results are injected into the parent as a synthetic text part (`injectBackgroundResult`), behind `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS`. — [V1 source: tool/task.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/tool/task.ts)
- V2: `agents` map or `.opencode/agents/<name>.md` (V1 dirs are still discovered); fields `description`, `mode`, `model: provider/model#variant`, `system`, `permissions`, `steps`, `disabled`. Sampling settings move to model variants (agent `request.body` "is kept but not sent to the model"). "Subagents run with fresh context in their own child sessions. They always run in the background". "A subagent uses its configured model, or inherits the parent session's model". The default nesting depth is one (`experimental.subagent_depth`). — [V2 docs: agents](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/agents.mdx), [V2 docs: tools](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/tools.mdx), [migrate-v1](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/migrate-v1.mdx)
- V2.3.0: "Subagents now always run in the background, return their session ID immediately, and report results to their parent whenever they become idle" (#63382). — [CHANGELOG](https://github.com/anomalyco/opencode/blob/dev/CHANGELOG.md)
- V2 stats separate `sessions` from `subagents` counts, and `SessionInfo.parentID` links them. — [V2 client types](https://github.com/anomalyco/opencode/blob/dev/packages/client/src/promise/generated/types.ts)
- V1 commands: `$ARGUMENTS`, `$1`, `$2` …, `` !`command` `` (for example `` !`git log --oneline -10` ``), `@src/components/Button.tsx`, and frontmatter `description`, `agent`, `model`, `subtask` ("useful if you want the command to not pollute your primary context"). — [V1 docs: commands](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/v1/content/commands.mdx)
- V2 commands live in `.opencode/commands/<name>.md` (`command/` is still discovered), with `subtask`→`subagent` and model `#variant`. "Delegated commands now run automatically in the background and report their results to the parent session." — [V2 docs: migrate-v1](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/migrate-v1.mdx)

### Inferences
- An SDD orchestrator can delegate each task (and each review pass) to a subagent with a minimal `prompt` and minimal tools. The parent then only accumulates short reports rather than whole file reads and test logs. That is a structural token saving, not just compression.
- Caveat: each child session re-pays the fixed prefix (system + tools + AGENTS.md), and V2 never warms subagent sessions. With 8–12 tasks this overhead is multiplied, so keep subagent prompts and tool sets small.

### Gaps
- I did not verify whether `!`shell`` output inside commands is truncated by `tool_output` limits.

## Q6. Prompt caching per provider and what breaks it

### Takeaway
V1 adds `cacheControl: ephemeral` breakpoints for Anthropic-like routes on the first 2 system messages and the last 2 non-system messages. It sets `promptCacheKey = sessionID` for OpenAI, Azure, xAI and Mistral (and others when `setCacheKey: true`). V2 adds explicit `compatibility.cacheFormat`, `settings.cache.ttl` and `warming`. Anything that changes an early byte invalidates the cached prefix: system edits, the date line, message-transform pruning, stripped reasoning, and tool-list changes.

### Cited Findings
- V1 `applyCaching`: `system = msgs.filter(role==="system").slice(0,2)`, `final = msgs.filter(role!=="system").slice(-2)`. Markers used: `anthropic.cacheControl {type:"ephemeral"}`, `openrouter.cacheControl`, `bedrock.cachePoint {type:"default"}`, `openaiCompatible.cache_control`, `copilot.copilot_cache_control` and `alibaba.cacheControl`. It applies when the model is Claude, `@ai-sdk/anthropic` or alibaba, and not `@ai-sdk/gateway`. — [V1 source: provider/transform.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/provider/transform.ts)
- V1 cache keys: when `providerOptions.setCacheKey !== false`, `prompt_cache_key = sessionID` is set for `@ai-sdk/deepinfra` and `@ai-sdk/cerebras`. `promptCacheKey = sessionID` is set for `@ai-sdk/openai`, `@ai-sdk/azure`, `@ai-sdk/xai`, `@ai-sdk/mistral`, `venice-ai-sdk-provider`, any provider with `setCacheKey === true`, and `opencode*` providers. `@ai-sdk/gateway` gets `gateway: {caching: "auto"}`. — [V1 source: provider/transform.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/provider/transform.ts)
- V1 image bounding is designed so that "the replaced prefix, and with it the provider's prompt cache, stays the same between cuts". — [V1 source: session/message-v2.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/message-v2.ts)
- V2 automatic breakpoints apply "on routes that are known to need them, such as Anthropic". For proxies (LiteLLM), set `compatibility.cacheFormat: "anthropic"`, which marks "the last tool definition, the system prompt, and the latest message". `"alibaba"` skips tool definitions. `settings.cache.ttl` on a provider or model sets Anthropic `"5m"`/`"1h"`; for OpenAI, `"24h"` maps to `prompt_cache_retention`. "Anthropic charges 2× the input price for a one-hour cache write and 1.25× for a five-minute one." `compatibility.supportsPromptCacheKey` controls `prompt_cache_key`, and `supportsEffortUpdates` "keep[s] the prompt cache" on effort changes. — [V2 docs: models](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/models.mdx)
- V2 `warming` (off by default) sends a keep-alive at 90% of `cache.ttl` (or every 4 min) for up to `duration` 30 min. "Subagent sessions are not warmed." Warming stops if a ping misses the cache. Warming requests are real billed requests. — [V2 docs: warming](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/warming.mdx)
- Known cache issues:
  - #5224 "System environment prompt causes cache invalidation" (closed 2025-12).
  - #5416 "Anthropic (and others) caching improvement" (closed; proposed per-agent TTL).
  - #29672 "Modify system prompt to improve cache hit rate" (closed).
  - #19081 "reasoning_content stripped from assistant messages on replay, causing KV cache invalidation on local inference" (llama.cpp with Qwen3.5 and GPT-OSS; cache diverged at about 18k tokens, causing reprocessing of about 19k tokens; fix PR #28352 proposed).
  - #23106 Bedrock `cache_point_ttl`.
  - [#5224](https://github.com/anomalyco/opencode/issues/5224), [#5416](https://github.com/anomalyco/opencode/issues/5416), [#29672](https://github.com/anomalyco/opencode/issues/29672), [#19081](https://github.com/anomalyco/opencode/issues/19081)
- DCP reports a cache hit rate of about 85% with pruning versus about 90% without. — [DCP README](https://github.com/Opencode-DCP/opencode-dynamic-context-pruning)

### Inferences
- Context-reduction plugins should edit only the tail of the conversation (newest tool outputs) or do so permanently at `tool.execute.after` time. Rewriting older messages on every call (ephemeral transforms) repeatedly busts the cache, and with caching providers that can cost more than it saves.
- With local llama.cpp, vLLM or Ollama, the "cache" is the server's prefix/KV cache. It affects latency and compute rather than billed tokens, but the same prefix-stability rules apply.

### Gaps
- I did not determine whether #19081's fix is merged in 1.19.6 or V2.

## Q7. Providers: OpenAI-compatible custom providers, local small models, GigaChat

### Takeaway
Both lines support any OpenAI-compatible endpoint. V1 uses `provider.<id>.npm: "@ai-sdk/openai-compatible"` with `options.baseURL` and `models.<id>.limit`. V2 uses `providers.<id>.package: "@opencode/ai/providers/openai-compatible"` with `settings.baseURL` and `models.<id>.{modelID, capabilities, limit}`. Set `limit.context`/`limit.output` correctly for small models, because they drive compaction thresholds. No opencode-specific GigaChat integration was found. GigaChat has a partly OpenAI-compatible API, but its access tokens expire every 30 minutes, so a proxy (gpt2giga or LiteLLM) or a token-refreshing plugin is needed.

### Cited Findings
- V1 example (llama.cpp): `"provider": {"llama.cpp": {"npm": "@ai-sdk/openai-compatible", "name": "...", "options": {"baseURL": "http://127.0.0.1:8080/v1"}, "models": {"qwen3-coder:a3b": {"name": "...", "limit": {"context": 128000, "output": 65536}}}}}`. `options.headers` are also supported. Models come from the models.dev catalog. — [V1 docs: providers](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/v1/content/providers.mdx)
- V2 custom provider: `"providers": {"local": {"package": "@opencode/ai/providers/openai-compatible", "settings": {"baseURL": "http://127.0.0.1:1234/v1", "apiKey": "{env:LOCAL_API_KEY}"}, "models": {"coder": {"modelID": "...", "capabilities": {"tools": true, "input": ["text"], "output": ["text"]}, "limit": {"context": 32768, "output": 8192}}}}}`. Unknown models fall back to "200,000-token context limit and 32,000-token output limit". — [V2 docs: models](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/models.mdx)
- V2 built-in local discovery covers Ollama (`http://127.0.0.1:11434`, only models with the `completion` capability), LM Studio (`http://127.0.0.1:1234/v1`) and vLLM (`http://127.0.0.1:8000/v1`, which uses `max_model_len`; "discovered vLLM models start with tools disabled"). — [V2 docs: providers](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/providers.mdx), [models](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/models.mdx)
- V2.3.0: "Providers can present a client certificate for gateways that require mutual TLS. Set `settings.tls` with `cert`, `key` and an optional `passphrase`". Local model discovery waits up to 15 s per request. — [CHANGELOG](https://github.com/anomalyco/opencode/blob/dev/CHANGELOG.md)
- GigaChat: the format is "частично совместим с OpenAI API". The base URL is `https://api.giga.chat/v1`. The access token is obtained via `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth` (`scope=GIGACHAT_API_PERS`) and "действует 30 минут". A `gpt2giga` proxy is mentioned. — [Sber developers: Совместимость с OpenAI](https://developers.sber.ru/docs/ru/gigachat/guides/compatible-openai), [gpt2giga](https://developers.sber.ru/docs/ru/gigachain/tools/utilities/gpttogiga-proxy-server). LiteLLM documents a GigaChat provider. — [LiteLLM GigaChat](https://docs.litellm.ai/docs/providers/gigachat)

### Inferences
- For GigaChat, run gpt2giga or LiteLLM locally and point an `@ai-sdk/openai-compatible` provider at it. An alternative in V1 is a plugin `auth` or `chat.headers` hook that refreshes the bearer token. GigaChat cache usage reporting was not documented, so `cache.read` will likely be 0.

### Gaps
- No public report of opencode used with GigaChat was found. Function-calling quality through the compatibility layer is unverified.

## Q8. Built-in tools and output limits; LSP

### Takeaway
V1 and V2 share the same default caps: read 2000 lines / 50 KB / 2000 chars per line, and generic tool output truncation at 2000 lines / 50 KB (configurable via `tool_output.max_lines`/`max_bytes`). The full output goes to a file, with a hint to grep or read with an offset. V1 edit/write append LSP diagnostics to tool results, which is a hidden token cost. V2 has no LSP.

### Cited Findings
- V1 read: `DEFAULT_READ_LIMIT = 2000` lines, `MAX_LINE_LENGTH = 2000` ("... (line truncated to 2000 chars)"), `MAX_BYTES = 50*1024` ("Output capped at 50 KB… Use offset=N to continue"). — [V1 source: tool/read.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/tool/read.ts)
- V1 generic truncation: `MAX_LINES = 2000` and `MAX_BYTES = 50*1024`, overridable by `tool_output.max_lines` and `tool_output.max_bytes`, with direction `head` or `tail`. The full text is saved to a file, and the model is told: "Full output saved to: <file>\nUse the Task tool to have explore agent process this file… Do NOT read the full file yourself". Without the task tool, the hint is "Use Grep… or Read with offset/limit". — [V1 source: tool/truncate.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/tool/truncate.ts)
- V1 shell default timeout is `2*60*1000` ms (`OPENCODE_EXPERIMENTAL_BASH_DEFAULT_TIMEOUT_MS`), and `MAX_METADATA_LENGTH = 30_000`. — [V1 source: tool/shell.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/tool/shell.ts)
- V1 `write` appends LSP diagnostics for the file and up to `MAX_PROJECT_DIAGNOSTICS_FILES = 5` other project files. `edit` appends diagnostics for the edited file. — [V1 source: tool/write.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/tool/write.ts), [tool/edit.ts](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/tool/edit.ts)
- V1 tool files: `apply_patch`, `edit`, `glob`, `grep`, `lsp` (`OPENCODE_EXPERIMENTAL_LSP_TOOL`), `plan`, `question`, `read`, `shell`, `skill`, `task`, `todo`/`todowrite`, `webfetch`, `websearch`, `write`, `code-mode`, `external-directory`, `invalid`. — [V1 source: tool/](https://github.com/anomalyco/opencode/tree/v1.19.6/packages/opencode/src/tool)
- V2 tools:
  - `read`: 2,000 lines / 50 KiB / 2,000 chars per line; images and PDFs up to 20 MiB.
  - `glob` and `grep`: default 100 results, 30 s timeout.
  - `edit`, `write`, and `patch` (patch for GPT models only).
  - `shell`: 2-minute default timeout; `background` option; "Large output is shortened and the complete output is retained in a managed file".
  - `webfetch` and `websearch`.
  - `question`, `skill`, and `subagent`.
  - `execute` (Code Mode: "processing results without adding every intermediate value to the model context"; MCP tools are reached through it by default).
  - Todos are behind `experimental.todo`.
  - — [V2 docs: tools](https://github.com/anomalyco/opencode/blob/dev/services/site/src/docs/content/tools.mdx)
- V2 `MAX_LINES = 2_000`, with `tool_output.max_lines` honoured in `core/src/shell.ts`. In 2.3.0, "Tool output truncation now keeps the beginning of the output". — [V2 source: core/src/tool-output.ts](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/tool-output.ts), [CHANGELOG](https://github.com/anomalyco/opencode/blob/dev/CHANGELOG.md)

### Inferences
- 50 KB is roughly 12k tokens per tool result. One full test-log dump per iteration × 3–5 review iterations × 8–12 tasks quickly dominates. Lowering `tool_output.max_bytes` and `max_lines` per project (for example 8 KB / 200 lines) is a zero-code, portable baseline A/B lever, and the full log remains in a file for targeted grep.
- In V1, LSP diagnostics after every edit can add tokens. Measure with LSP enabled and disabled (`lsp` config / `OPENCODE_DISABLE_LSP_DOWNLOAD`).

### Gaps
- The exact V1 config key for disabling LSP per project was not verified in this pass.
