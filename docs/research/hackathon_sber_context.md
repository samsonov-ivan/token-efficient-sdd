## 3. GigaChat API details relevant to measuring tokens (usage, counting, caching, pricing, context, function calling, OpenAI compatibility)

### Takeaway
GigaChat responses include `usage` with `prompt_tokens`, `completion_tokens`, `total_tokens` and **`precached_prompt_tokens`** (cached tokens, which are not billed). Prompt caching is driven by the **`X-Session-ID`** header. There is a **POST /tokens/count** endpoint. The single base URL since July 2026 is **https://api.giga.chat** (OpenAI-style base `https://api.giga.chat/v1`). OpenAI compatibility is only partial, and the gpt2giga proxy fills the gap. GigaChat 2 Max has a 128K context window and costs 650 ₽ per 1M tokens. Individuals get 365M free freemium tokens, which is enough for A/B runs.

### Cited Findings
- **Caching via `X-Session-ID`:** the header is optional and "может содержать произвольную строку". Without it, the server assigns a uuid4. When requests share the same ID and partly matching context, the model doesn't recompute that context. Listed use cases include "ассистенты для написания кода, которые кэшируют кодовую базу" and caching function-call results. The page says optional headers are supported "только в Python-библиотеках GigaChat", but its curl examples include the header too. In the Python SDK the ID is set through `gigachat.context.session_id_cvar.set(...)`. The page does not say which models support caching. — [developers.sber.ru, Работа с историей чата](https://developers.sber.ru/docs/ru/gigachat/guides/keeping-context)
- **`usage` fields:** `prompt_tokens` = "Токены запроса, после вычитания кэшированных токенов". `completion_tokens` = generation tokens. `precached_prompt_tokens` = "Кэшированные токены из предыдущих запросов. Вычитаются из общего количества токенов, подлежащих тарификации". `total_tokens` = billable total after the cache deduction. — [developers.sber.ru, Подсчёт токенов](https://developers.sber.ru/docs/ru/gigachat/guides/counting-tokens)
- **POST `/tokens/count`:** takes the message strings and the model name (the SDK example is `giga.tokens_count(input_=[...], model="GigaChat-Pro")`). It cannot estimate generation tokens or count tokens in files or images. "В среднем в одном токене 3—4 символа". Function descriptions and the message history in `messages` count toward tokens. — [developers.sber.ru, Подсчёт токенов](https://developers.sber.ru/docs/ru/gigachat/guides/counting-tokens); [API reference link](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-tokens-count)
- **OpenAI compatibility:** "формат сообщений GigaChat API частично совместим с OpenAI API". You set `base_url="https://api.giga.chat/v1"` and pass an access token as `api_key`. The token comes from OAuth at `https://ngw.devices.sberbank.ru:9443/api/v2/oauth` with `scope=GIGACHAT_API_PERS`, and "Токен доступа действует 30 минут". The page recommends gpt2giga for redirecting OpenAI requests. — [developers.sber.ru, Совместимость с OpenAI](https://developers.sber.ru/docs/ru/gigachat/guides/compatible-openai)
- **Changelog (2026):** 16.07.2026, a single endpoint "https://api.giga.chat" for individuals and legal entities. 15.07.2026, GigaChat 3 Ultra available to individuals in Freemium. 06.10.2026, parallel function calls in `POST /v2/chat/completions` (with GigaChat 3 Ultra). 22.05.2026, assistant messages gained a `function_call` field. 26.06.2026, structured output (`chat_parse()` with Pydantic). 22.06.2026, a `docs-mcp` MCP server for the documentation. 22.07.2026, freemium raised to 365,000,000 tokens. 01.09.2026, new individual packages are valid for 1 month. — [developers.sber.ru, changelog](https://developers.sber.ru/docs/ru/gigachat/changelog)
- **Models available via API:** GigaChat 3 Ultra ("доступная физлицам в рамках freemium-режима"), GigaChat 2 Max, GigaChat 2 Pro and GigaChat 2 Lite ("Быстрая и легкая модель для простых повседневных задач"). — [developers.sber.ru, Модели](https://developers.sber.ru/docs/ru/gigachat/models). GigaChat 3 Ultra's API name is `GigaChat-3-Ultra`. "Физлица и юрлица на платных тарифах доступа к Ultra пока не имеют". — [GigaChat 3 Ultra page](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-3-ultra)
- **GigaChat 2 Max:** context window "128 000" tokens, "Поддержка функций", image input, 650 ₽ per 1M tokens. — [GigaChat 2 Max page](https://developers.sber.ru/docs/ru/gigachat/models/gigachat-2-max)
- **Individual tariffs:** freemium is "365 000 000 бесплатных токенов": 250M Lite (`GigaChat`/`GigaChat-2`), 40M Pro, 25M Max and 50M GigaChat 3 Ultra. The fetch summary says each is valid for 12 months; this was not independently verified. Paid packages: Lite 20M for 1,300 ₽ (about 65 ₽ per 1M), Pro 3M for 1,500 ₽ (about 500 ₽ per 1M), Max 3M for 1,950 ₽ (about 650 ₽ per 1M). "Генерация текста выполняется в одном потоке" (one concurrent request for individuals). - **TypeScript function schemas:** GigaChat 3's chat template writes function descriptions in TypeScript syntax instead of JSON, which Sber says "can cut token use by up to 30%". — [Habr, SberDevices: GigaChat 3 release, 21 Nov 2025](https://habr.com/ru/companies/sberdevices/articles/968904/)

### Inferences
- **Two-layer measurement:** use GigaChat's `usage` (including `precached_prompt_tokens`) as ground truth and log it per pipeline stage. Report both raw prompt tokens and billable tokens after caching, because a stable prefix with `X-Session-ID` lowers billable tokens without changing the content. That is a cheap, measurable win to show in the A/B. Keep the prefix byte-stable, since even a reordered tool output can break caching (see section 6).
- **Concurrency:** individual accounts run one generation thread, so A/B runs will be sequential. Plan run time on the evening of 21 Nov.
- **Small vs large via API:** GigaChat-2 (Lite) and GigaChat-2-Max, or GigaChat-3-Ultra on freemium, give a natural pair for the universality criterion through the same API. The freemium allowance (250M Lite, 25M Max, 50M Ultra) is enough for several full SDD runs.
- **Pricing table for the report:** the gap between Lite (about 65 ₽) and Max (about 650 ₽) per 1M tokens supports a "model routing per stage" argument: cheap model for reading and summarising, large model for design and code.

## 5. GigaCode: agent mode, CLI, relation to opencode; connecting GigaChat to opencode

### Takeaway
GigaCode has an agentic mode, distributed through GitVerse. Sber also ships GigaCode Desktop (multi-agent) and a GitVerse agentic pipeline with BYOK (Bring Your Own Key). No source says that GigaCode or the GitVerse agent is built on opencode. **GigaChat can be connected to opencode through the official gpt2giga proxy.** The gpt2giga repository ships a ready `opencode.json` that uses `@ai-sdk/openai-compatible` for GigaChat-2, -2-Pro and -2-Max.

### Cited Findings
- **gpt2giga** is a "FastAPI proxy for OpenAI, Anthropic and Gemini compatible clients backed by the GigaChat API". The default address is `http://localhost:8090`. It supports `POST /chat/completions`, `POST /responses`, `POST /embeddings`, `GET /models`, Anthropic `POST /messages` and `POST /messages/count_tokens`, and Gemini routes. It maps tools/function calling, structured output and SSE streaming. "GigaChat не является drop-in заменой OpenAI или Anthropic API." The README names Codex, Claude Code and Gemini CLI as working clients. Install with `pip install gpt2giga`. The latest stable version appears to be 0.3.1; 0.3.3a1 is a candidate release. — [GitHub ai-forever/gpt2giga](https://github.com/ai-forever/gpt2giga); [Sber docs page for gpt2giga](https://developers.sber.ru/docs/ru/gigachain/tools/utilities/gpttogiga-proxy-server)
- **The repo's `opencode.json`** defines providers "GigaChat-Lite" (model `GigaChat-2`, baseURL `http://localhost:8090`), "GigaChat-Pro" (`GigaChat-2-Pro`, `:8091`) and "GigaChat-Max" (`GigaChat-2-Max`, `:8092`, `"limit": {"context": 128000, "output": 128000}`). All use `"npm": "@ai-sdk/openai-compatible"`. — [raw opencode.json in gpt2giga](https://raw.githubusercontent.com/ai-forever/gpt2giga/main/opencode.json)

- **GigaCode agentic mode:** works autonomously with files, handles tasks from codebase analysis to a finished solution, supports 35+ languages and major IDEs, and is downloadable on GitVerse. — [CNews](https://zoom.cnews.ru/soft/news/line/2026-06-19_ot_assistentov_k_agentam/print)

## 6. Russian-language community discussion on token economy in AI coding agents and SDD

### Takeaway
Russian Habr and vc.ru content on SDD (Spec Kit, OpenSpec) and token savings is mostly anecdotal. Authors openly admit they have no measurements. This leaves room for a hackathon team that brings controlled, reproducible measurements. Recurring techniques: narrow each run's scope, use sub-agents with only the relevant plan fragment, choose the context-gathering tool by task complexity, and keep prompt prefixes byte-stable so the provider cache keeps working.

### Cited Findings
- **OpenSpec on Habr** («Не болтайте ерундой», 5 Jan 2026, 42K views). Workflow: `openspec init` (creates AGENTS.md), `openspec/project.md`, then a proposal in `openspec/changes/<id>/` with `proposal.md`, `tasks.md` and `specs/<cap>/spec.md`, then `/openspec:apply`, then `/openspec:archive`. Install with `npm install -g @fission-ai/openspec`. No token measurements: 13 tasks in `tasks.md` were left undone, and the article compares Kiro, Spec Kit and OpenSpec subjectively. — [Habr 983062](https://habr.com/en/articles/983062)
- **Spec Kit roadmap** (28 Jul 2026): "Контекстное окно кончается раньше, чем фича." Problems appear after about the first 30 tasks. Fixes: limit each run (for example, tasks T001–T010 then stop with a report), use sub-agents that each get one task and the relevant plan fragment, split work into sub-specs, and keep a table of reusable code so the agent doesn't rewrite modules. The author's verdict: "Пока это гипотеза без единого замера." — [Habr 1063940](https://habr.com/ru/articles/1063940/)
- **Lightweight Spec Kit in Cursor** (4 Aug 2026): no separate plan or tasks files, because extra files "увеличивают шум для модели". The human sets the approval status. Update only changed specs instead of re-specifying everything. — [Habr 1066276](https://habr.com/ru/articles/1066276/)
- **21 context-gathering tools compared** (3 Jun 2026; Agno with gpt-4.1-mini, judged by gpt-5.4-nano). On the medium task, ugrep took 2,697 tokens and passed, while read-all + repo_map took 175,208 tokens and failed. On the hard task, codex_like went 6/6 at 861K tokens while Serena (an LSP/symbol-graph tool) went 6/6 at 79K tokens, about 11× fewer. The metric used is "successes per 1,000 tokens" (SPT). Conclusion: match the tool to the task's complexity. — [Habr 1042880](https://habr.com/ru/articles/1042880/)
- **vc.ru, 17 local MCP servers** (24 May 2026): context volume cut by 75.5% on 25 tasks. Key point: byte reduction isn't enough, because a non-deterministic compressor breaks the provider's prefix cache. A file-search step returned results in a different order in about 7 of 10 runs, and sorting fixed it. "Одно большое сжатие на одном ходе не окупает потерю кэша на каждом следующем." The exact cache-hit numbers were withheld. — [vc.ru](https://vc.ru/dev/2945685-sokrashchenie-raskhoda-tokenov-v-claude-code-s-lokalnymi-mcp)
- Other Russian how-to posts on Claude Code token savings exist, but were not reviewed in depth: [vc.ru «Экономим токены…»](https://vc.ru/ai/2874028-ekonomiya-tokenov-v-claude-code); [vc.ru «Как сократить расход токенов в Claude Code»](https://vc.ru/anetrebskii/2857194-kak-snizit-rashod-tokenov-v-claude-code); [Habr 1027882](https://habr.com/ru/posts/1027882/)

### Inferences
- **Differentiator:** almost no Russian community article backs SDD token claims with measurements. A team that delivers a reproducible per-stage token ledger (requirements, proposal, specs, design, tasks, implementation, review, verification), with repeated runs and variance, directly addresses the 35% "savings confirmed by measurement" and 15% "which stages consume most" criteria.
- **Metric:** an SPT-style metric (success per 1K tokens) plus test pass rate is a ready-made, citable way to show "quality preserved" alongside savings.
- **Caching check:** the cache-stability insight applies directly to GigaChat's `X-Session-ID` / `precached_prompt_tokens`. Report cached-token share before and after, and make the context builder deterministic (sorted file lists, stable ordering).

### Gaps
- No Russian-language source measuring OpenSpec token use per stage was found.
- No SberTech-authored community post on token economy was found.
