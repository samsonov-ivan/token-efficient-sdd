# Форматы Frugal v1

В [манифесте](../schemas/manifest.schema.json) хранится единица наблюдения — одна попытка одного плеча. Ее каталог получает уникальный run ID. Поле `dry_run` отделяет техническую репетицию от вызовов провайдера. Даже завершённый dry-run подтверждает только работу стенда. Для платёжных данных `null` означает неизвестное значение. Статус серии определяется отдельно от статуса процесса.

`purpose: h03-pilot` обозначает техническую пару H-03 вне конкурсного сравнения. Поле `experiment` равно `null`. Для обоих плеч сохраняются метрики расхода и результаты тех же гейтов качества, что для B0. Эти попытки исключаются из конкурсных пар, серий и когорт калибровки.

В [calls.jsonl](../schemas/call.schema.json) одна строка соответствует одному вызову. Идентичность задаёт `event_key`. Сверка источников дополняет эту запись. У каждого вызова есть ссылка на первичное событие. Только пять известных непересекающихся компонент дают RPT. При конфликте или неизвестной величине измеритель сохраняет известный расход, а итог, пригодный для сравнения, остаётся пустым.

[findings.json](../schemas/findings.schema.json) описывает структурированное ревью. В стандартном B0 исходная рецензия сохраняется в естественном формате. [frugal.yaml](../schemas/frugal.schema.json) описывает конфигурацию целевого проекта. В базовом плече каждое значение из `flags` выключено. Исходные определения метрик и правил сравнения находятся в [ТЗ](../TZ.md).

Изменения опубликованных контрактов регистрируются в [журнале решений](DECISIONS.md). Цены, конфигурации и журналы предназначены для передачи без учётных данных.
