# Учёт модельных вызовов

`frugal meter <run-dir>` пересчитывает один запуск из сохранённых файлов. Команда работает офлайн и требует `sqlite3` с поддержкой JSON. Нужны `manifest.json`, stdout `opencode run --format json` в `raw/events.jsonl` (или `raw/events/*.jsonl`) и консистентная резервная копия отдельной базы запуска в `raw/opencode.db`. Экспорт `opencode export SESSION` можно положить в `raw/export.json` или `raw/exports/*.json`. Для фикстуры с `dry_run: true` допустим замкнутый набор экспортов без базы. Корневая сессия и границы стадий задаются в `manifest.stages`. Дочерние сессии наследуют стадию родителя.

Снимайте базу после остановки фоновых задач через SQLite backup API или `sqlite3 /path/to/opencode.db '.backup /path/to/capture.db'`. Скопируйте полученный файл в каталог сырья. Измеритель открывает снимок в режиме immutable, сверяет суммы таблицы `session` с отдельными `step-finish`, присоединяет фактические модель и провайдера из `message`, проверяет дубликаты по `part.id`. При нескольких неразличимых стадиях подготовки спецификации расход попадает в `spec`. Другие неоднозначные стадии получают `other`. Подробнее в [формате V1](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/core/src/session/sql.ts) и [реализации команды stats](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/cli/cmd/stats.ts).

При работе без полного журнала запросов провайдера задавайте уникальный `--title` каждой новой сессии и фиксируйте в манифесте `metering.title_disabled: true`. В V1 встроенная генерация названия обрабатывает только текст ответа, usage теряется. Измеритель указывает границу наблюдения `opencode-only`. Совпадение локальных источников проверяет восстановление счётчиков внутри процесса. Для дополнительной независимой проверки используйте журнал endpoint. [Генерация названия в 1.19.6](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/prompt.ts#L178-L224)

В опциональном `raw/provider.jsonl` храните только поля usage и идентификаторы привязки. Для каждой попытки указывайте уникальный `request_id`, `provider_id`, `model_id`, `session_id`, `source_schema`, исходный объект `usage` и `ts`. Для обычного шага нужен `part_id` из opencode. Для отдельного оплаченного повтора используйте `kind: retry`, `attempt` и, если известен, `retry_part_id`. Служебный запрос получает `kind: service`. Неполный файл заблокирует итог. Семантика `openai-chat` вычитает закэшированный вход из суммы входа и reasoning из суммы выхода. В `anthropic-messages` кэш-входы учитываются отдельно, весь output остаётся в `t_out`, поскольку отдельный счётчик thinking в этом формате отсутствует. Формат `opencode-v1` уже содержит непересекающиеся счётчики. [OpenAI Chat usage](https://developers.openai.com/api/reference/resources/chat) · [Кэширование в Anthropic Messages](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) · [Нормализация opencode](https://github.com/anomalyco/opencode/blob/v1.19.6/packages/opencode/src/session/session.ts#L321-L357)

Команда создаёт `calls.jsonl`, `stages.csv` и `meter.json`. Ключ `raw_sha256` в сводке содержит SHA-256 каждого использованного исходного файла. Для проверки архива отдельным прогоном выполните `frugal meter <run-dir> --out <новый-каталог>` и сравните отпечатки и суммы. Для каждого вызова `raw_ref` ведёт к строке JSONL, JSON pointer экспорта или записи в SQLite. Массив `sources` позволяет перепроверить все копии. В сводке `known_rpt` содержит однозначно подтверждённые значения, `complete` описывает полноту учёта, `rpt` и `cost` при ошибке равны `null`. Код возврата 1 и массив `issues` указывают на пропуск или расхождение. Сохранённый `cost` соответствует оценке opencode или указанной стоимости провайдера. Проверяйте цены запуска перед использованием суммы в отчёте.

Для повторения WP-00 smoke сначала запустите `node scripts/probe-opencode.mjs mock`. Затем передайте родительскую папку выведенного каталога evidence и новый путь для артефактов в `node scripts/meter-probe.mjs <probe-root> <new-run-dir>`. Для проверки учёта дочерней сессии выполните `node scripts/check-meter-children.mjs <new-run-dir>` после сборки. Скрипт запускает V1 вне проекта и записывает запросы локального HTTP-провайдера. Обе команды добавляют `reconciliation.json`. У технических прогонов `kind: meter-smoke` и отсутствует пара измерений.
