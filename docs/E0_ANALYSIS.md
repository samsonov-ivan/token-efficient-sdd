# Офлайн-анализ E0 и E0-s

До запуска зафиксируйте классы моделей и ожидаемые run ID в декларации калибровки. После запуска укажите все состоявшиеся попытки из этой серии, включая прерванные. Поле `experiment` в манифесте должно совпадать с классом серии. Технические smoke и пилоты Ф0 со своими идентификаторами сохраняются в исходных архивах. Декларация имеет следующую структуру.

~~~json
{
  "cohorts": {
    "M-M": {"model": "provider/medium", "runs": ["e0-mm-1-base-a1"]},
    "M-L": {"model": "provider/large", "runs": ["e0-ml-1-base-a1"]},
    "M-S": {"model": "provider/small", "runs": ["e0-small-1-base-a1"]}
  }
}
~~~

Запустите анализ из корня репозитория.

~~~bash
uv run --project analysis python analysis/e0.py \
  --runs bench/runs --cohorts /path/to/e0-cohorts.json --out report
~~~

Команда создаёт `e0.md` и `e0.svg`, ссылается на исходные манифесты и нормализованный журнал и работает без модели. Один завершённый конвейер с полным расходом даёт одно наблюдение по RPT. Результат приёмки показывается отдельно. Прерванные попытки отражаются в таблице и исключаются из распределения завершённых прогонов. Когорта с повторяющимся слотом или дрейфом закреплённых входов остаётся без агрегатов до выяснения причин.

Ставьте флаг `--fixture` только при проверке анализатора на dry-run архивах с манифестами E0/E0-s. В этом режиме отчёт получает явную маркировку. Объёмы и выводы для Ф1 проверяются по ТЗ и заносятся в реестры отдельно. Живому раннеру нужен заранее зарегистрированный план и бюджет. Анализатор читает готовый архив.

Для M-M и M-L зарегистрируйте два файла бюджета в `bench/plans/`, например `e0-mm.json` и `e0-ml.json`. Передавайте раннеру `--experiment E0 --budget-plan e0-mm` или `--experiment E0 --budget-plan e0-ml`, с отдельным `--series` для каждой когорты. Имя плана выбирает бюджет и параметры запуска. Оба манифеста сохраняют `experiment: "E0"`. Для M-S используйте `--experiment E0-s` с отдельным планом. Перед живыми вызовами сверяйте закреплённый SHA раннера, dry-run для выбранного профиля, бюджет и остаток квоты. [Параметры раннера](../tools/runner/README.md)

Пересчёт N показывает чувствительность к неизвестной корреляции парных плеч. На графике шкала RPT своя для каждого класса, а полосы стадий показывают долю суммарного RPT на шкале от 0% до 100%. Решение о перестановке кандидатов относится к живым данным и фиксируется по §15.5. [Методика и протокол](../TZ.md)
