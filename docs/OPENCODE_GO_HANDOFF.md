# OpenCode Go для тестов Frugal

## Ответ координатору про провайдера и бюджет

Провайдер — **OpenCode Go (`opencode-go`)**. Владелец разрешил использовать **всю оставшуюся квоту действующей подписки Go** на тесты Frugal. Лимит дополнительных списаний с баланса — **$0**. Для первых полноценных B0 на модели среднего класса предлагается `opencode-go/deepseek-v4.1-flash`.

На момент проверки кабинета 21 ноября 2026 года было израсходовано 50% месячной квоты и 0% недельной и 5-часовой. `Use credit` был выключен, баланс составлял $0. Подписка была настроена на отключение 30 ноября. Квота общая для моделей Go и расходуется с разной скоростью в зависимости от модели. Перевод остатка в токены возможен только после замера на конкретной модели. При исчерпании квоты останови очередь до сброса лимита. [Лимиты и Extra Usage](https://opencode.ai/docs/console/go/#usage-limits)

## Как запускать

- Запускай оба плеча через закреплённый в проекте `opencode run --format json` с одной моделью, провайдером и параметрами. CLI и прямой Go API дают доступ к тем же моделям подписки. Сквозной запуск CLI сохраняет агентный цикл с инструментами, файлами, командами и тестами. MCP-обёртка наследует квоту Go и для раннера не нужна. [Подключение Go и API](https://opencode.ai/docs/console/go/#endpoints)
- Передавай авторизацию в окружение изолированного процесса через переменную или игнорируемый `.env` согласно правилам проекта. На момент проверки ключ Go в окружении CLI был недоступен. Ключ через чат, манифесты, исходные журналы и отчёты передавать нельзя. [Авторизация API](https://opencode.ai/docs/console/api/inference/#authentication)
- Для отдельных бесплатных проверок в кабинете был включён `opencode-go/hy4-flash-free`. Доступность следует проверять из закреплённого CLI. Подменять модель в одном плече или посреди пары при исчерпании квоты запрещено. [Модели OpenCode](https://opencode.ai/docs/models/)

## Что проверено

- В кабинете Go открыт реальный потоковый запрос `deepseek-v4.1-flash` через `/inference/go/openai/v1/chat/completions`. В журнале есть ID запроса и сессии, HTTP-статус, причина завершения, задержка до первого токена, длительность, вход, выход, reasoning, чтение из кэша и стоимость. Этот запрос был сделан ранее из OpenCode Desktop.
- OpenCode **1.19.6** проверен на двух локальных потоковых ответах Chat Completions. В первом контроле родительский CLI показал два шага, SQLite добавил один шаг подагента. `frugal meter` учёл все три вызова и получил те же 46 809 RPT, что и тестовый провайдер. Совпала разбивка по полям. [Манифест](../bench/runs/wp02-go-usage-smoke-20261121/manifest.json) · [Сверка](../bench/runs/wp02-go-usage-smoke-20261121/reconciliation.json)
- Во втором контроле в расширении Go передали 50 токенов записи в кэш на вызов. CLI и SQLite показали `t_in=454` и `t_cache_write=0` вместо ожидаемых `t_in=404` и `t_cache_write=50`. Общий RPT при этом сошёлся. Стоимость по прайсу из расширения Go в `step_finish` не появилась. [Манифест](../bench/runs/wp02-go-cache-write-smoke-20261121/manifest.json) · [Сверка](../bench/runs/wp02-go-cache-write-smoke-20261121/reconciliation.json)

Числа из локальных контролей относятся к тестовым ответам. Живой поток Go через прокси, платные ретраи и служебные вызовы на Go ещё не проверены. Во время этой проверки новых запросов к Go не было. Подробности и пути к сырым событиям записаны в [EXP-20261121-02](EXPERIMENTS.md#exp-20261121-02-разбивка-токенов-opencode-go).

## Что собирать для отчёта

| Источник | Данные |
|---|---|
| `step_finish` и изолированная SQLite | Шаги, ID сессий и сообщений, связь с подагентами, привязка к стадиям через манифест |
| Исходный финальный `usage` Go через прокси | Токены по категориям, ID запроса, модель, статус и попытка, списание, прайс и расход квоты. В Chat Completions usage приходит в финальном чанке при `stream_options.include_usage` |
| Манифест и гейты | Модель и параметры, версии, этапы, время всей фичи, качество и результаты скрытых тестов |

В расширении `usage.opencode.tokens`, если оно пришло, `input` уже исключает кэш, а `output` включает reasoning. Для непересекающихся полей Frugal вычитай `reasoning` из `output` и складывай `cache_write_5m` с `cache_write_1h`. По завершении запроса сохраняй исходный `usage` без преобразований для аудита. При отсутствующем или неоднозначном usage отмечай пробел; не подставляй ноль без проверки семантики поля. [Документация полей](https://opencode.ai/docs/console/api/inference/#cost)

В пределах подписки `usage.cost` может быть нулевым. `usage.opencode.list_cost` показывает стоимость по прайсу, `usage.opencode.allowance` — расход квоты подписки. Храни их раздельно. Для M4 фиксируй цены в манифесте по правилам ТЗ. [Метрики §4.1](../TZ.md#41-метрики-токенов) · [Документация полей](https://opencode.ai/docs/console/api/inference/#cost)

Прокси должен сохранять сеансовый заголовок, нужный Go для маршрутизации и кэша, и пропускать поток без изменения запросов и ответов, кроме запроса финального `usage`, если CLI сам его не включил. Сопоставляй вызовы по идентификаторам. Сверяй число вызовов и каждую категорию токенов наряду с порогом расхождения общего RPT <1% по ТЗ. Отдельно проверяй оплаченные ретраи и служебные вызовы. [Требования Go к клиентам](https://opencode.ai/docs/console/go/#where-can-i-use-it) · [Учёт токенов §10.2](../TZ.md#102-учёт-токенов-и-атрибуция-стадий)

## Порядок работы

1. Сверь текущее состояние гейтов и сделай `--dry-run` через актуальный раннер. Используй свежий клон и отдельные каталоги opencode для каждого прогона. [Изоляция §10.1](../TZ.md#101-окружение-и-изоляция-обязательно)
2. После подключения ключа сделай короткий живой контроль на `opencode-go/deepseek-v4.1-flash`. Проверь `billing_source`, `allowance` и соответствие финального `usage` данным CLI и SQLite. Сохрани артефакты в `bench/runs/`.
3. Если Ф0 всё ещё открыт, проведи два полных автономных B0 на модели среднего класса по стратегии и проверь гейты. Перед серией из более чем двух прогонов оцени её расход по фактическому замеру с запасом 30% и зафиксируй объём, бюджет и правило остановки в `docs/EXPERIMENTS.md`. [Стратегия](../STRATEGY.md#5-как-провести-работу-за-оставшееся-время) · [Бюджет §10.7](../TZ.md#107-бюджет)
