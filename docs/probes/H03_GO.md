# Техническая проверка H-03 в OpenCode Go

Оба плеча получают одну открытую историю из 24 коммитов и одну задачу. OpenCode 1.19.6 вызывает `git log --oneline` и возвращает хеш коммита с заданным заголовком. В OPT плагин сокращает вывод и модель читает архив. Проверка требует точного хеша из обоих плеч, меньшего вывода OPT и побайтного совпадения архивного журнала с исходным. Перед каждым плечом создаётся чистая копия фикстуры и свежее окружение OpenCode. Модель `opencode-go/deepseek-v4.1-flash`, `max`, образ, команды и доступы одинаковы. Меняется флаг `tool_output_compression`.

## Запуск и повторный учёт

```sh
npm run build
node scripts/probe-compression-go.mjs --dry-run \
  bench/runs/h03-go-dry frugal-runner:local-24
```

Репетиция подставляет loopback-ответы с искусственным расходом и прогоняет штатный relay, CLI и учёт через SQLite. В живом режиме используется только подписка Go. До запуска проверьте в авторизованном кабинете **Extra Usage выключен, доступный кредит $0**. Подтверждение передаётся флагом `--live-extra-usage-off`. Живой режим использует `OPENCODE_API_KEY` из окружения координатора. OpenCode в Docker получает одноразовый ключ loopback relay.

```sh
node scripts/probe-compression-go.mjs --live-extra-usage-off \
  bench/runs/h03-go-live frugal-runner:local-24 bench/runs/h03-go-dry
node_modules/.bin/frugal meter bench/runs/h03-go-live/base
node_modules/.bin/frugal meter bench/runs/h03-go-live/opt
```

Каждый вызов сверяется с relay и SQLite. Если Go возвращает ошибку авторизации или квоты, не сообщает источник биллинга либо списывает средства с баланса, relay прекращает очередь. Этот контроль проверяет ответ, поэтому отключение Extra Usage в кабинете перед первым вызовом обязательно.

`summary.json` связывает две технические проверки и показывает вызовы, RPT, его пять компонент, расход подписки и списание с баланса для каждого плеча. В `base/` и `opt/` сохранены манифест, события CLI, provider usage из relay, снимок SQLite и расчёт `meter.json`. В `opt/raw/full-git-log.txt` доступен точный оригинал архива. В общий RPT OPT входит дополнительный вызов после чтения файла. Этот сценарий проверяет один инструмент и восстановление архива. Приёмка Ф0 и оценка эффективности H-03 на полной фиче требуют отдельных прогонов.
