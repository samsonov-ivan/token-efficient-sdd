# Проверка H-01 в OpenCode V1

На двух открытых задачах свежий сеанс передал за всю реализацию 58 902 байта, продолженный — 60 946. Разница в 2 044 байта пришлась на повторную передачу истории первой задачи. Исходные восемь POST доступны для офлайн-проверки. [Скачать запросы, журналы и отчёт](h01-apply-requests.zip)

```sh
npm ci && npm run build
archive_dir=$(mktemp -d)
unzip -q docs/probes/h01-apply-requests.zip -d "$archive_dir"
node scripts/probe-live-opt.mjs --verify-apply-context "$archive_dir/h01-apply-requests"
```

Из корня checkout с зависимостями из `npm ci` и версией Node из `.node-version` выполните две команды.

```sh
npm run build
node scripts/probe-live-opt.mjs
```

Первая строка вывода `Evidence:` указывает каталог результата вне проекта. Для независимого пересчёта подставьте его путь в следующую команду.

```sh
node scripts/replay.mjs /path/to/native-h01
```

В открытой фикстуре установленный OpenCode 1.19.6 создаёт через свои инструменты артефакты OpenSpec и два текстовых файла. Локальный HTTP-сервер выдаёт случайный идентификатор первой задаче. Второй сеанс получает принятый handoff, записывает квитанцию и проходит отдельный публичный тест. Полное ревью запрашивает документирование формата, затем проверяет исправление. Стадия verify проверяет итоговое дерево Git.

`probe.json` содержит ID обоих apply-сеансов, дерево и число запросов. `opt/quality-review.json` связывает отзывы со снимками и транскриптами. Измеритель сверяет `raw/events.jsonl` с экспортами OpenCode в `raw/exports/`. Результаты `gate-*.tap` относятся к публичным тестам этой фикстуры. Команда проверяет нативный исполнитель и учёт на ответах локального сервера с фиксированным usage. Независимая приёмка конкурсной задачи и измерение экономии требуют отдельной живой пары.

## Объём HTTP-запросов на стадии apply

Команды ниже повторяют опыт и независимо пересчитывают байты из сохранённых тел запросов. Для первого вызова укажите новый каталог. Второй работает офлайн.

```sh
capture="bench/runs/h01-context-$(date +%s)"
node scripts/probe-live-opt.mjs --compare-apply-context "$capture"
node scripts/probe-live-opt.mjs --verify-apply-context "$capture"
```

После полной проверки конвейера скрипт повторяет две задачи с одинаковым текстом, включая handoff. В плече `fresh` каждая задача получает свой сеанс OpenCode. В `continued` вторая задача продолжает первый сеанс через `--session`. Оба плеча используют одинаковые абсолютные пути и Git-деревья из исходного прогона, отдельные каталоги данных, одинаковую модель-фикстуру и набор инструментов. Каждый вызов задачи выполняет одну настоящую запись файла и получает итоговый ответ. Проверяются совпадение результата с исходным снимком и успешное выполнение публичного теста каждой задачи.

`context.json` содержит разбивку по плечам и задачам. `body_bytes` — длина полученного HTTP-тела, `messages_bytes` включает все системные, пользовательские, ассистентские и инструментальные сообщения, `tools_bytes` учитывает объявления инструментов. `other_body_bytes` охватывает прочие поля и синтаксис внешнего JSON. В каталогах `fresh/` и `continued/` лежат восемь неизменённых тел POST, журналы CLI и результаты тестов. Пересчёт проверяет их, сравнивает текущий диалог и подтверждает совпадение параметров запроса.

Это контроль влияния истории на два коротких задания при одинаковом handoff. Размеры относятся к UTF-8-телу Chat Completions до транспортного сжатия. Оценку в токенах, платёжный кэш и результаты на конкурсном репозитории этот опыт не устанавливает. [Сводка с SHA-256 исходных тел](../../bench/runs/summary/h01-apply-request-bytes.json)
