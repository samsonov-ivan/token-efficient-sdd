# Проверка среды WP-00

Команда запускает настоящие бинарные файлы закреплённых версий. Для каждого запуска она создаёт временный Git-репозиторий вне проекта со своими HOME, каталогами XDG, конфигурацией opencode и журналом плагина. Все назначения модели, включая small_model, указывают одного провайдера. У сессии заранее задано название. Выход сохраняется в `bench/runs/wp00-<режим>-<id>/`. Это техническая проверка до Ф0.

## Воспроизведение с mock

```sh
npm ci
npm run setup:v2
npm run build
node scripts/probe-opencode.mjs mock
```

`summary.json` содержит результаты проверок. `openspec-validate.stdout` показывает строгую валидацию change. После MODIFIED и archive `openspec-show.stdout` содержит единственное изменённое требование с исходным REQ и SCN в именах. `openspec-instructions.stdout` и `openspec-status.stdout` содержат штатные структуры apply/status. V1 обнаруживает проектный skill в `.agents/skills/`; mock-сервер фиксирует его имя в фактическом запросе. `v1-plugin.jsonl` показывает вход server(), `v2-plugin.jsonl` — вход setup(). Для V2 пакет указывается через `plugins: ["./frugal-plugin"]`, сервер запускается командой `debug agents --standalone`. При проверке без доступа к loopback нужен локальный запуск с разрешением на прослушивание временного порта.

## Настоящий локальный ответ

На Apple Silicon используется официальный сервер MLX-LM с весами HuggingFaceTB/SmolLM2-360M-Instruct. Скрипт сверяет SHA-256 файла весов и версии через метаданные пакетов, запускает процесс на loopback в режиме Hugging Face offline и завершает его при выходе. Одноразовый прокси передаёт исходный JSON штатному серверу и сохраняет запрос и ответ SSE. В запросе модель получает короткую команду ответить «hi». [Модель и закреплённая ревизия](https://huggingface.co/HuggingFaceTB/SmolLM2-360M-Instruct/tree/a10cc1512eabd3dde888204e902eca88bddb4951) · [Официальный выпуск MLX-LM](https://pypi.org/project/mlx-lm/0.32.2/)

```sh
# Из корня проекта после успешной проверки mock.
runtime_dir="$(mktemp -d)"
uv venv --python 3.12 "$runtime_dir/env"
uv pip install --python "$runtime_dir/env/bin/python" \
  'mlx-lm==0.32.2' 'mlx==0.32.4' 'mlx-metal==0.32.4' \
  'transformers==5.23.0' 'huggingface-hub==2.4.0' 'tokenizers==0.23.3'
# hf download использует уже имеющийся кэш при совпадении ревизии.
export FRUGAL_MODEL_SNAPSHOT="$("$runtime_dir/env/bin/hf" download HuggingFaceTB/SmolLM2-360M-Instruct \
  --revision a10cc1512eabd3dde888204e902eca88bddb4951 \
  --include 'model.safetensors' '*.json' 'merges.txt')"
export FRUGAL_MLX_ENV="$runtime_dir/env"
export FRUGAL_MOCK_SUMMARY="$PWD/bench/runs/wp00-mock-<id>/summary.json"
sh scripts/probe-mlx.sh
```

Для сверки доступны `provider-request.json`, `provider-response.sse`, `v1-events.stdout`, `v1-export.stdout`, `v1-stats.stdout`, `opencode.db` и `summary.json`. RPT пересчитывается из поля usage ответа поставщика и сопоставляется с `step_finish` в opencode. Экспорт содержит фактическое имя модели, ответ и идентификатор сессии. Проверка публикует признак успеха после обнаружения положительного usage и загрузки обеих версий плагина. При ошибке сохраняются доступные журналы. При двух запусках путь временного репозитория в системном промпте может изменить длину входа.
