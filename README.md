# Frugal SDD

**Сколько токенов можно сэкономить на одной законченной фиче?** Команда разрабатывает `frugal` для кейса СберТеха на хакатоне Студсовета ФПМИ. Сравниваем обычный и оптимизированный процессы OpenSpec + opencode на одинаковых требованиях, модели и провайдере. В обеих ветках остаются спецификация, реализация, LLM-ревью и проверка. Экономию подтверждают записи вызовов, а качество — тесты и связи между требованиями, задачами и кодом.

Запись для просмотра длится 1 минуту 57 секунд. В архиве рядом с видео лежат отчёт и исходные события открытой демонстрационной пары. [Скачать комплект](docs/collaboration/defense-preview.zip) · [Проверить решение по пяти критериям жюри](docs/JURY.md)

## Запуск прототипа

Из корня checkout используйте Node из `.node-version`, Python ≥3.11, uv, Git и sqlite3. Парная репетиция запускается без ключей и внешней модели. Новый каталог сохраняет исходные события, отчёт и дашборд.

```bash
npm ci
npm run build
demo_dir=$(mktemp -d)
node_modules/.bin/frugal run --mode paired --feature add-transfer-limits \
  --flag session_per_task --dry-run --series prototype --out "$demo_dir/runs"
node scripts/replay.mjs "$demo_dir/runs"
node_modules/.bin/frugal report "$demo_dir/runs" --out "$demo_dir/report"
ls "$demo_dir/report"
```

Откройте `REPORT.md` и `dashboard.html` в `$demo_dir/report`. Парная репетиция проверяет изоляцию, создание артефактов и воспроизводимость учёта. Измеренная экономия на живой паре пока не установлена. [Контур качества](docs/QUALITY.md) · [состояние живых прогонов](docs/STATE.md)

Открытая фикстура с включёнными оптимизациями проверяет выдачу капсул, инкрементальное ревью после правки и полную проверку итогового состояния. Её можно вызвать отдельно.

```bash
node_modules/.bin/vitest run packages/cli/tests/run.test.ts \
  -t 'executes the capsule and review flags'
```

Для проверки самого плагина в OpenCode V1 и V2 выполните `npm run setup:v2` и `node scripts/probe-compression.mjs "$demo_dir/compression.json"`. Проверка на локальной фикстуре измеряет длину сжатого журнала и сверяет SHA-256 оригинала, который OpenCode может прочитать после сжатия. [Сохранённая сводка](bench/runs/summary/h03-native-loopback.json) · [команды Docker-репетиции](tools/runner/README.md)

Передачу контекста между задачами можно проверить в установленных OpenCode 1.19.6 и 2.3.2. После `npm ci` и `npm run setup:v2` выполните `npm run check:handoff`. Локальный провайдер выдаёт разовое значение и проверяет, что оно попало во вход второй сессии. Команда печатает реальные ID сессий и каталог событий. [Сводка проверки](bench/runs/summary/h01-native-opencode.json)

Запись показа с отдельными сессиями задач, капсулами, структурированным ревью и проверкой сжатия можно собрать из открытой фикстуры. [Команды записи](docs/VIDEO.md#показ-прототипа-на-открытой-фикстуре)

Разработчикам доступны `npm test` и `npm run test:analysis`. Если у вас есть архив живых попыток, пересчитайте его теми же командами `scripts/replay.mjs` и `frugal report`, передав путь к архиву. [Измеритель и экспорт](docs/METER.md) · [замороженный B0](docs/baseline/B0.md) · [контроли демо-репозитория](bench/features/QA.md)

## Как запустить разработку

Открой этот репозиторий в Codex и отправь **«делай»**. [Правила агента](AGENTS.md) направят его к [стартовому промпту](docs/START_PROMPT.md) и [единой стратегии на 27 часов](STRATEGY.md). Для внешнего автоматического запуска передай содержимое стартового промпта как задание с рабочим каталогом в корне репозитория.

## С чего начинается эксперимент

1. Воспроизвести стандартный процесс на чистом демо-репозитории. По каждому обращению к модели записать сырые токены, стадию и статус. Проверить покрытие требований и сценариев работающими тестами.
2. По расходу стадий выбрать первые оптимизации. Кандидаты включают короткие сессии с дословными требованиями задачи, выдачу только нужных фрагментов файлов и логов, инкрементальное ревью после первого полного просмотра. Каждый метод можно включить отдельно.
3. Сравнить ветки парными прогонами, повторить на моделях разного размера и сторонних репозиториях. Сохранить все попытки и собрать из них отчёт. Сырые токены, стоимость и качество имеют отдельные метрики.
