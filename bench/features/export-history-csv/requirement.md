# Выгрузка операций в CSV

Добавить `GET /accounts/{id}/history.csv`. Публичный API счетов и переводов продолжает работать. Время всех операций UTC, суммы — целые копейки.

## REQ-CSV-01. Представление

- SCN-CSV-01.1. У существующего счёта ответ 200, media type `text/csv`, UTF-8 без BOM, разделитель запятая, строки завершаются CRLF по RFC 4180. Первая строка всегда `id,created_at,source,destination,amount,type`.
- SCN-CSV-01.2. Пустая история состоит из одной строки заголовков. У неизвестного счёта 404 с JSON `{"error":{"code":"account_not_found"}}`.
- SCN-CSV-01.3. Строка содержит id операции как десятичное целое, created_at в UTC с суффиксом Z, буквальные идентификаторы счетов, целую сумму и направление относительно выбранного счёта; применяется стандартное CSV-экранирование (например ID `shop,1`).

  Для ранее сохранённых операций `created_at` в CSV обозначает тот же момент UTC, что и в исходной записи.

## REQ-CSV-02. Выбор операций

- SCN-CSV-02.1. Печатать каждую связанную операцию ровно один раз, по целому id по возрастанию. Чужие переводы исключены.
- SCN-CSV-02.2. Необязательный query `type=incoming|outgoing` отбирает соответствующее направление; неизвестное значение — 422 `invalid_export_query`.
- SCN-CSV-02.3. Необязательные `from` и `to` — даты YYYY-MM-DD включительно по UTC, обе независимы и сочетаются с type; неверная дата или обратный период дают 422 `invalid_export_query`. Формат всех ошибок тот же, что в SCN-CSV-01.2.

  `from=2026-01-02` включает операцию в `2026-01-02T00:00:00Z`. `to=2026-01-02` включает операцию в `2026-01-02T23:59:59Z` и исключает операцию в `2026-01-03T00:00:00Z`. Если обе даты равны, период охватывает один полный день UTC.

  Допустимы крайние даты `0001-01-01` и `9999-12-31`. Фильтр `from=0001-01-01` включает подходящую операцию в первый момент этой даты, а `to=9999-12-31` включает подходящую операцию в `9999-12-31T23:59:59Z`. Для ранее сохранённых операций действуют те же границы, в том числе если в исходной метке времени год записан без ведущих нулей.

## Задачи приёмки

Пять задач с тестами: выбор связанных операций; отбор периода и направления; сериализация и экранирование; HTTP-ответ со всеми ошибками; интеграционная проверка пустой истории, границ и принадлежности операций. Создание CSV ничего не меняет в базе.

Использовать идентификаторы задач `1.1`…`1.5` в указанном порядке и вышеприведённые ID требований и сценариев во всех артефактах.
